# 04 プロトタイプ作成

面白さを、作って遊んで確かめる部門。最後に縦切りを作る。

## 仕事人と呼ぶ順

1. プリプロの問いごとに `game-proto-programmer` を呼ぶ（問いが互いに関係なければ、問いごとに**同時に**）
2. できたものに `game-proto-playtester` を呼ぶ。作った担当の説明は渡さない（問いと起動方法だけ）
3. プロデューサーが「続ける／直して続ける／捨てる」を決める。直すなら 1 に戻る（同じ問いで3回直してもだめなら、捨てるか柱を見直す）
4. 問いに「はい」がそろったら、**縦切り**を作る
5. オーナーに縦切りを見せて **ゲートB**

## 問いの立て方

- 1つのプロトで1つ。答えが「はい／いいえ」で出る形にする
- よい例：「ジャンプの溜めの長さで飛距離が変わる操作は、10回で思いどおりに飛べるようになるか」
- 悪い例：「面白いか」

## 縦切り（バーティカルスライス）

- ゲームの小さな一部（1ステージ、1戦闘など）を、プログラム・絵・音・UI・演出のすべてで、製品に近い品質まで作ったもの
- 目的は、最後まで作るとこうなる、をオーナーとチームが同じ絵で持つこと。そして、その品質で作れることを確かめること
- 縦切りは、本番の土台に移す前提で作ってよい（05 の設計担当に、持ち込む部分を渡す）
- 小さなゲームでは、プロトをそのまま育てて縦切りにしてよい

## ゲートB（オーナー）

- プロトの問いすべてに「はい」が出た（「いいえ」のものは、仕掛けを変えるか捨てると決めた）
- 縦切りが起動し、遊べる。オーナーが遊べる起動方法とスクリーンショットがある
- オーナーが「この方向で作り込む」と言った

## この部門に加わる仕事人

中心の仕事人（上の「呼ぶ順」）に加えて、プロジェクトに要るときに呼ぶ。`開発チーム.md` で使わないと決めた仕事人は呼ばない。

| 仕事人 | 職種 | この部門でやること |
|---|---|---|
| `game-design-director` | ゲームディレクター、ディレクター | プロトの「続ける／捨てる」を最終判定する |
| `game-design-creative-director` | クリエイティブディレクター | 縦切りが「この作品らしさ」を持っているか |
| `game-design-systems` | システムデザイナー、ゲームプレイデザイナー | プロトで仕組みの手ざわりを確かめる問いを出す |
| `game-design-combat` | コンバットデザイナー、バトルデザイナー、スキルデザイナー、キャラクター能力設計担当 | 戦闘の手ざわりを確かめるプロトの問い |
| `game-design-ux` | UXデザイナー、UIデザイナー、チュートリアルデザイナー | プロトで、わかりやすさを確かめる問いを出す |
| `game-art-director` | アートディレクター、リードアーティスト | 縦切りの見た目が、製品の品質の見本になっているか |
| `game-anim-animator` | アニメーションディレクター、リードアニメーター、3Dアニメーター、モーションデザイナー、フェイシャルアニメーター | プロトで、手ざわりに関わる動き（予備動作の長さ）を確かめる |
| `game-qa-usability` | ユーザビリティテスター | プロトで、操作のわかりやすさを測る |
| `game-rnd-engineer` | 研究開発エンジニア、AI研究者、機械学習エンジニア | プロトで、新しい技術の試作（スパイク） |
