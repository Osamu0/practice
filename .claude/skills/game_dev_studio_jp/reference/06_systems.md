# 06 ゲームシステム

ゲームの仕組みを本番のコードに実装する部門。07 コンテンツ、08 統合と並べて回す。

## 仕事人と呼ぶ順（タスクごと）

1. バックログから、依存のないタスクを選ぶ。担当（`game-sys-gameplay`、`game-sys-ai`、`game-sys-ui`）に渡す。同じファイルを触らないタスクは**同時に**呼ぶ（同じファイルを触るものは順に）
2. できたら `game-sys-code-review` を呼ぶ
3. 「必ず直す」を担当に戻す。通ったら、バックログの状態を「完了」にしてコミット
4. 数タスクごとに、08 の統合で通しのビルドが壊れていないか確かめる

## 実装で仕様が足りなかったとき

- 担当は勝手に決めず、未決として返す。プロデューサーが、小さなことはその場で決めて仕様に書き足す。大きなことは 03 に戻す
- 担当が決めた細かい数値は、パラメータ表に足す

## ゲート（タスクごと）

- 完了条件（機能仕様の受け入れ条件）を満たし、テストが通る
- コードレビューの「必ず直す」が0
- 通しのビルドが起動する

## この部門に加わる仕事人

中心の仕事人（上の「呼ぶ順」）に加えて、プロジェクトに要るときに呼ぶ。`開発チーム.md` で使わないと決めた仕事人は呼ばない。

| 仕事人 | 職種 | この部門でやること |
|---|---|---|
| `game-design-director` | ゲームディレクター、ディレクター | 実装が手ざわりの狙いに合うかを見る（数タスクごと） |
| `game-design-systems` | システムデザイナー、ゲームプレイデザイナー | 実装中の仕様の穴を埋める |
| `game-design-combat` | コンバットデザイナー、バトルデザイナー、スキルデザイナー、キャラクター能力設計担当 | 実装中の戦闘の仕様の穴を埋める |
| `game-design-ai` | AIデザイナー | 実装されたAIを遊んで、狙いと違うところを返す |
| `game-design-ux` | UXデザイナー、UIデザイナー、チュートリアルデザイナー | 実装された画面を見て、設計と違うところを返す |
| `game-design-social` | ソーシャルシステムデザイナー | 実装中の穴を埋める |
| `game-tech-director` | テクニカルディレクター | 大きな実装の方針（新しい仕組みの入れ方）を判定する |
| `game-tech-engine` | エンジンエンジニア、システムプログラマー、物理演算プログラマー | 当たり判定、物理、メモリ、読み込みの仕組み |
| `game-tech-graphics` | グラフィックスプログラマー | シェーダー、光、後処理、粒子の仕組み |
| `game-tech-network` | ネットワークプログラマー | 同期、遅延への手当て、切断と再接続 |
| `game-tech-backend` | サーバーエンジニア、バックエンドエンジニア、データベースエンジニア | 機能ごとのAPIの実装とテスト |
| `game-tech-security` | セキュリティエンジニア、セキュリティテスター、不正対策担当、情報セキュリティ担当、セキュリティ会社スタッフ | 守るものの一覧と対策の設計、実装 |
| `game-tech-performance` | パフォーマンスエンジニア、パフォーマンステスト担当 | 性能の目標と測り方を決め、重い実装を早めに見つける |
| `game-audio-engineer` | サウンドエンジニア、ミキシングエンジニア、レコーディングエンジニア、音響制作会社スタッフ | 音を鳴らす仕組みの実装（グループ、優先度、同時に鳴る数） |
| `game-pm-manager` | プロジェクトマネージャー、プロダクションマネージャー、制作進行担当、リソースマネージャー、アシスタントディレクター | 進行の報告（タスクごとの状態、遅れ、詰まり） |
| `game-qa-lead` | QAディレクター、QAマネージャー、QAリード、リードQA | 品質の方針とテストの戦略を早めに決める（何を自動で、何を人で） |
| `game-qa-automation` | 自動テストエンジニア | 機能ごとの受け入れ条件を自動テストにする |
| `game-ops-analyst` | データアナリスト、ゲームアナリスト、データサイエンティスト | 記録の実装を確かめる |
