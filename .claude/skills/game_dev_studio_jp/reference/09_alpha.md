# 09 アルファ版

全部の機能が入り、最初から最後まで通して遊べることを確かめる部門。ここから先は、機能を足すのではなく、仕上げる工程になる。

## アルファの条件

- 必須の機能がすべて入っている（仮の見た目・仮の音・仮のテキストは残ってよい）
- 最初から最後まで、通して遊べる（止まる、進めなくなる場所がない）
- 落ちる・データが消えるなどの致命的なバグが、わかっているものは全部バグ表にある

（スタジオによって「アルファ」の線の引き方は違う。このスキルでは上の条件をアルファとする。`sources.md`）

## 仕事人と呼ぶ順

1. `game-alpha-judge` と `game-alpha-playtest` を**同時に**呼ぶ
2. プロデューサーが、判定とプレイテストをまとめ、`09_アルファ/判定.md` と `プレイテスト記録.md` に書く。バグは `10_ベータ/バグ表.md` を作って入れる
3. 判定が「通らない」なら、足りない機能を 06〜08 に戻す
4. 面白くない場所が大きければ、04 に戻ってその部分だけプロトで確かめ直す
5. オーナーに、判定、プレイテストの要約、遊べるビルドを渡して **ゲートC**

## ゲートC（オーナー）

- アルファ判定が「通る」か「条件つきで通る」
- ここで機能を確定する。オーナーが「この機能で出す」と言った。以降の機能の追加は、リリース後に回す

## この部門に加わる仕事人

中心の仕事人（上の「呼ぶ順」）に加えて、プロジェクトに要るときに呼ぶ。`開発チーム.md` で使わないと決めた仕事人は呼ばない。

| 仕事人 | 職種 | この部門でやること |
|---|---|---|
| `game-biz-executive` | 代表取締役、エグゼクティブプロデューサー、事業責任者 | アルファで、出す時期・規模を変えるべきかを判定する |
| `game-design-director` | ゲームディレクター、ディレクター | アルファで、残す・削るを決める材料を出す |
| `game-design-creative-director` | クリエイティブディレクター | 通して遊んで、印象がぶれる場所 |
| `game-tech-director` | テクニカルディレクター | アルファで、技術的な残りの山（性能、安定）を見る |
| `game-art-director` | アートディレクター、リードアーティスト | 通しで見て、品質のむらを挙げる |
| `game-pm-manager` | プロジェクトマネージャー、プロダクションマネージャー、制作進行担当、リソースマネージャー、アシスタントディレクター | アルファに向けた残りの量の見積もり |
| `game-pm-secretary` | 会議・情報管理担当、教育担当 | 決めたことの記録の見直し（古い決め、食い違い） |
| `game-qa-lead` | QAディレクター、QAマネージャー、QAリード、リードQA | アルファの品質の報告（バグの数、重さ、増え方） |
| `game-qa-usability` | ユーザビリティテスター | アルファで、主な課題（始める、設定、保存、進む）を測る |
| `game-release-store` | ストア管理担当 | ストアページの初版（何を見せるか） |
| `game-mkt-director` | マーケティングディレクター、ブランドマネージャー | 発売までの宣伝の山の計画 |
| `game-mkt-planner` | マーケティングプランナー、マーケティング担当、広告運用担当、イベントプランナー、広告代理店スタッフ | 体験版・展示・配信の計画 |
| `game-mkt-community` | SNSマーケター、コミュニティマネージャー、インフルエンサーマーケター | SNSの投稿の型と予定、コミュニティのガイドライン |
| `game-mkt-pr` | PR担当、広報担当、PR会社スタッフ | プレスキットの初版、発表の文 |
| `game-mkt-creative` | トレーラー監督、モーショングラフィックスデザイナー、グラフィックデザイナー、Webデザイナー、カメラマン、コンテンツマーケター、映像制作会社スタッフ | トレーラーの構成・絵コンテ、公式サイトの初版 |
| `game-sales-publisher` | パブリッシャー、セールスマネージャー、営業担当、流通管理担当 | 販売計画（`宣伝/販売計画.md`）：売る場所、地域、時期、数の見込み |
