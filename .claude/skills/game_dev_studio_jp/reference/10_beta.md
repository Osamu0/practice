# 10 ベータ版

コンテンツを確定させ、バグを潰し、遊び心地を詰める部門。新しい機能もコンテンツも足さない。

## ベータの条件（入るとき）

- アルファのゲートCを通った
- 仮の資産を本番に差し替える作業が終わっている（終わっていなければ、最初にそれを 07 でやる）

## 仕事人と呼ぶ順

1. `game-beta-firsttime` を呼ぶ（起動方法だけを渡す。仕様、ほかの人の指摘は渡さない）
2. バグ表の重い順に `game-beta-bugfix`、プレイテストの指摘順に `game-beta-polish` を呼ぶ。同じファイルを触らないものは**同時に**
3. 直したものは、`game-qa-tester` に回帰テストをさせて閉じる（11 の担当を先に借りてよい）
4. 直したら、もう一度 `game-beta-firsttime` を呼ぶ（前回と同じ担当の記憶は持ち越さないので、初見として遊ぶ）
5. 大きな迷いと致命・重大のバグがなくなるまで 2〜4 を回す → ゲート10

## バグ表の型（`10_ベータ/バグ表.md`）

| ID | 要約 | 再現手順 | 期待 | 実際 | 頻度 | 重さ | 状態 | 原因・直し |
|---|---|---|---|---|---|---|---|---|

- 重さ：**致命**（落ちる、データが消える、進めない）／**重大**（大事な機能が動かない、回避できるが痛い）／**軽微**（不便）／**見た目**
- 状態：新規 → 確認済み → 直した（確認待ち）→ 閉じた／直さない（理由）

## ゲート10

- コンテンツが確定し、仮の資産がない（残すものは理由つき）
- 致命のバグが0、重大のバグは0か、残す理由がオーナーに伝わっている
- 初見テストで、最初の5分に大きな迷いがない

## この部門に加わる仕事人
