# 11 品質保証・最終審査

出してよいかを決める部門。テスト、規約と権利の審査、リリース判定をする。

## 仕事人と呼ぶ順

1. `game-qa-tester`（テスト計画 → 実行 → バグ報告）と `game-qa-compliance`（審査）を**同時に**
2. 見つかったバグは 10 の `game-beta-bugfix` に戻して直し、`game-qa-tester` が回帰テストで閉じる
3. 審査の「否」は、持ち主の部門に戻して直す（素材の差し替え、クレジットの追加、文言の直し）
4. 全部そろったら `game-qa-release-judge`
5. 判定をオーナーに渡して **ゲートD**

## テストの範囲（既定）

- 機能：すべての受け入れ条件
- 境界：0、最大、同時、連打
- 中断：ポーズ、タブの切り替え、画面の大きさを変える、途中で閉じる
- 保存：保存と読み込み、古い版のセーブ（アップデート時）
- 長時間：30分以上の連続プレイで重くならないか
- 性能：目標のフレームレート
- 表示：画面の大きさ、文字の切れ、ローカライズ
- アクセシビリティの設定が効くか

## 審査の項目（既定）

- 配信先のプラットフォームの要件（その時点の公式の資料で確かめる）
- 素材、フォント、ライブラリのライセンスとクレジット
- 既存の作品に似すぎていないか
- 年齢区分に関わる表現、プライバシー、課金の表示

## リリースの条件

- きれいな状態から同じビルドが作れる
- 自動テストが全部通る。テスト計画の項目が全部合格か、残す理由がある
- 致命・重大のバグが0
- 審査の「否」と「わからない」が0（「わからない」が残るなら、オーナーに伝えて決めてもらう）
- 版番号、変更履歴、クレジット、ストア用の文と画像がそろっている

（「マスターアップ／ゴールド」は、出すと決めた最終のビルド。このスキルでは、ゲートDを通ったビルドをそう呼ぶ）

## ゲートD（オーナー）

- リリース判定が「出せる」
- オーナーが「出す」と言った。出したら、版のタグを付けてコミットする
