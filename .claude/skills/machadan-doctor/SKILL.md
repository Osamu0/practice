# マチャダン Doctor（4.13.4）

正本を推測で書き換えず、配布物・セーブ・実際の配置から導入、更新、破損を調べる。
未定義の物語や補充待ちは修復エラーではない。総点検は導入・更新・異常時に行い、
通常ターンの確認はGMのbegin-turnに任せる。

## 手順

1. `references/repair-policy.md` を読む。対象パス、版、既存セーブ、バックアップを確認する。
2. まず読取専用の総点検を実行する。

   ```bash
   MACHADAN_WORKSPACE=.claude python3 machadan_spade/muse版/tools/check_knowledge.py \
     --root machadan_spade/muse版 --strict --anchors --json
   ```

3. 結果を分類する。空の在庫や未確定プロフィールは正常。必要な空容器だけが欠けた時は
   inventory-initで作れる。見本在庫の自動投入や、好み・職業の推測は行わない。
   更新時の全廃棄は検証済みセットアップが版切替時に一度だけ行う。
   同版の再検査・再導入やGMの通常操作でinventory-resetを実行しない。
4. セーブはvalidate-saveで検証し、旧形式、または版・manifest更新だけの警告がある時にmigrate-save --in-placeで履歴付き更新を行い、再検証する。v3の構造が同じ場合も版情報は更新する。
   正本・索引・manifest・ツールの破損は、その場で作り直さず、配布ZIPのsetup.py --check-onlyを通して
   検証済み配布物からstaging復旧する。保存済みの人物、進行、所持品、出目は保持する。
5. 意味上の問題では`../machadan-gm/references/canonical-recheck.md` を読む。
   このSKILL.mdの階層を起点に隣のGMスキルへ進む相対パスである。
   正本が一意なら反映漏れを直す。正本同士で解決できない衝突だけ、具体箇所を示して確認する。
6. pending取引は保存された同じ候補・input・run_id・transaction IDで復旧する。
   補充の世代やキャンペーンが変わった古いpayloadを再投入しない。新しい出目や別の在庫を引いて代用しない。
7. 修復後に総点検を行い、セーブと開始contextを確認する。.claude/skills/ に2スキルがあり本文まで読めるか確認する。
   現行方式がこの環境で使えないと確認できた時だけ旧互換の入口を配置する。
   カタログ更新待ちだけなら配置成功・検出保留を分けて報告する。

## 完了報告

本体配置、セーブ移行、スキル検出、補充登録、補充の実行結果を別々に短く報告する。
セットアップが返した未完了の操作を最後まで確認し、スキル検出はdetected／pending／legacyの実測値を記録する。
外部の補充登録が有効でも、新版で未実行ならその点を明記する。
失敗は「本番変更前に中止」「元に戻して一致確認済み」「復旧に要確認」を実際の結果で区別する。

## 守ること

- セーブ、所持品、物語の確定事実を空状態で上書きしない。
- 在庫だけは新版へ切り替える時に作り直す。旧在庫の形式移行を要求しない。
- 導入済みのanchorsやmanifestを--fixで作り直してエラーを消さない。
- 作者の数値・人物・料金・世界設定や、利用者のNGを修復の名目で変更しない。
- 正本不明の不足をダミーファイルで隠さず、未定義の創作は自由に進める。
- 自動補充スケジュールを利用者の了承・既存設定の確認なしに作成・有効化しない。

## 診断の実行時間 (4.13.4)

導入・検証は経過時間だけで打ち切らない。呼出し側の待機が終わっても、実行が継続しているなら同じ実行IDと終了コードを確認する。再起動や検証の省略へ切り替えず、同じ診断を重ねて起動しない。
