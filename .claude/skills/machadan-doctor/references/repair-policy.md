# 修復方針（4.13.0）

## 自動で扱える範囲

- 欠けたディレクトリと、最新版の空の在庫容器を作る。
- 定義済みの旧セーブ移行を履歴付きで実行し、検証する。
- セットアップによる版切替時に、可変在庫を全廃棄して新しい世代の空容器へ切り替える。
- 現在の世代・キャンペーンで中断した取引を、保存された同じ入力とIDで再試行する。
- キャッシュだけを限定的に除外・掃除する。正本とコードのハッシュ検査は維持する。

inventory-initは不足した空容器を用意するだけで、見本seedから人物や出来事を入れない。
ヒアリング完了後に人物、職業確定後に依頼の入荷を要求する。未確定や在庫ゼロは正常な準備待ちである。
通常の検査・同版再導入・GM進行で在庫を全廃棄しない。inventory-resetは検証済み更新の版切替専用。
旧seed同期は新しい更新方針として使用せず、旧在庫を最新版形式へ無理に移行しない。

## 自動で変更しない範囲

作者の数値、料金、確率、年齢、人物・世界設定、同順位の正本の衝突、利用者のNG、
キャンペーンの結果や既存セーブの進行、確定済みダイスcursorは推測で変更しない。
未定義の人・場所・出来事を世界に合わせて作ることは通常プレイであり、修復対象ではない。

## 問題の分類

| 区分 | 例 | 扱い |
|---|---|---|
| 準備待ち | ヒアリング途中、職業未定、在庫ゼロ | 正常。必要な時だけ確定セーブから少数入荷し、創作で進行可 |
| 容器不足 | 在庫ファイル自体がない | inventory-initで空容器を用意。見本を投入しない |
| 中断 | 現在世代の補充やセーブ取引がpending | 同じ入力・候補・IDで再試行し検証 |
| 古い補充 | 世代・キャンペーン・確定情報が不一致 | 再投入しない。現在の確定セーブから新しい要求を作る |
| 移行・版更新 | 旧セーブスキーマ、旧版/manifestのメタ情報 | 履歴付きmigrate-save、再検証 |
| 意味の衝突 | 現行正本が異なる数値を断定 | 正本を再照合し、解決できない具体箇所だけ確認 |
| 配布物の破損 | 必須正本・索引・ツール・manifestの欠落や改変 | 検証済み配布物からstaging復旧 |

## 検証済み配布物による復旧

導入済み本体のcheck_knowledge --fixは使わない。anchors.jsonとmanifestは配布物であり、
破損現場から索引・ルーティング表・ハッシュを再生成して正常扱いにしない。
復旧元ZIPでsetup.py --check-onlyを通し、その配布物のセットアップを使う。
セーブと確定した世界の事実、再試行用のセーブ候補・取引記録は保つ。
新版へ更新する時だけ在庫を作り直し、古い補充専用payloadや在庫用記録を新世代へ混ぜない。
同版での復旧では在庫を維持する。

## 失敗と復旧の確認

staging検証の成功前に本番を切り替えない。セーブ移行は履歴を残し、失敗した元ファイルを保つ。
本番切替後の検査失敗は元へ戻し、一致確認が成功した時だけ復旧済みと報告する。
戻せたか不明な時や検証失敗時に、成功と断定しない。
