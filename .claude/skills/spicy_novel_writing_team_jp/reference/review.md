# 校閲（受け持ちとまとめ方）

## 受け持ち

> `spicy_novel_writing_jp` のファイルごとに、どの校閲が見るかを決めておく。全部のファイルに担当がいるようにして、抜けをなくす。作品の文体ルールの節も、作品の `執筆チーム.md` でどの校閲が見るかを決める。

| `spicy_novel_writing_jp` | 担当 |
|---|---|
| `author_edits.md`（台詞の温度） | キャラ口調 |
| `dialogue.md`（話し言葉、声の区別、♡・笑、「…」、表記、台詞の読点） | キャラ口調（台詞）、文章（表記・読点） |
| `realism.md`（リアルにする、行為の組み立て） | キャラ口調（台詞）、読者（場面の目的・リアルさ）、エロ（混ざりあい）、整合（体勢） |
| `ai_tells.md` | AIっぽさ |
| `narration.md`（地の文、読点、行為中の地の文の量、落差、場面の切り方） | 文章（読点・量・二重書き）、エロ（落差・生々しさ） |
| `sounds.md`（擬音、喘ぎ声） | 文章（表記・長さ）、エロ（強さ・形） |
| `inner_voice.md` | キャラ口調 |
| 作品の設定・本文メモ・前の章 | 整合 |

## 呼び方

- 6人（整合、文章、キャラ口調、エロ、AIっぽさ、読者）を同時に呼ぶ
- 作品で足す校閲（作品の `執筆チーム.md`）があれば、同時に呼ぶ
- 文体サンプルは全員が見本として読むが、整合は「設定と合っているか」の比べる相手にしない。代わりに「サンプルの台詞・出来事・喘ぎのかたまりを本文に使っていないか」を見る

## 指摘の形（全員共通。メンバーのファイルにも書いてある）

- 行番号、該当の文（そのまま引用）、何が問題か、直し案（そのまま差し替えられる文）
- 重さ：**必ず直す**（読者が引っかかる、食い違い、誤用）／**直したほうがいい**（もっとよくなる）
- 自分の役割の範囲に絞る。問題がなければ「なし」

## 編集長のまとめ方

- 同じ行への指摘を並べて、採るものを決める
- ぶつかったときは、作品の設定・文体ルール・`spicy_novel_writing_jp` に近いほうを採る
- AIっぽさの指摘が、甘さや感情を削る方向なら採らない
- 地の文を減らす指摘で、喘ぎ声が説明台詞になるなら採らない（地の文を縮めるほうにする）
- 指摘が場面全体に及ぶとき（台詞の往復が薄い、段取りになっている、など）は、その場面を `novel-writer` に戻す。台詞の往復が薄いなら、掛け合いからやり直す
- 新しく見つかった型（AIっぽさ、作者が嫌いそうな書き方）は、`spicy_novel_writing_jp` の `feedback_loop.md` に沿って、スキルか作品のルールに足すかを決める
