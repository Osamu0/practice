# 開封前線（仮）

game-concept-planner、2026-11-24。芯にしたのはアイデア出しの 29（攻めてくるパック）で、24（ハズレ・重複がレンガになる）と 33（流れ弾で連鎖して開く）を組み込んだ（プロデューサーが選んだ案A）。
タイトルは仮のもの。ほかの案は「未決」に書いた。事実は `01_企画/市場調査.md`（以下「市場調査」）から引いた。印のない数字は、この企画書での見積もりか提案。

## 一文の企画
iPhone を縦に持った1人のプレイヤーが、道を進んでくる封をされたパックを、集めたキャラで撃って開け、出てきたキャラを道ばたに置き直して、次のもっと硬いパックを開けていく。開けた中身がすぐ自分の戦力になり、開ける数が1個から何万個へと桁で増えていくのが気持ちいいゲーム。

## コアの面白さ
- **プレイヤーの動詞**
  - **開ける**：撃って封を割る。割れたら中身が飛び出す。開封も撃破も同じ一瞬に起きる
  - **置く**：出てきたキャラを、道ばたのマスに置く。置き替える
  - **積む**：重複とハズレはレンガになる。どの壁に積むかを選ぶ
  - **呼ぶ**：次に流れてくるパックの強さ（硬さと中身の良さ）を自分で上げる
  - **刷り直す**：転生（やり直し）。ここまでの道を捨てて、新しいルールのある道に行く
- **そのときの気持ち**
  - 封にひびが入る → 「もう少しで開く」。割れる → 「何が出た？」
  - レアが出る → 「これを置けば、あの硬いパックが割れる」。出たものがすぐ次の作戦になる
  - 重複が出る → 「壁が高くなる」。ハズレでもがっかりで終わらない
  - 連鎖して周りのパックがまとめて開く → 「狙いどおり」「一度に全部割れた」
  - 数が桁で増える → 最初は1個ずつだったのが、まとめて開けて、自動で開けて、気づけば何万個。その中のレアだけが大きく光る
- **1回の遊び**（見積もり）
  - パック1個：数秒（撃つ → 割れる → 中身が飛び出す）
  - 流れ1段（パックの群れを1つさばく）：30〜90秒
  - 転生1回：最初は数十分。登り直すたびに短くなるようにする（市場調査 3：好かれる転生は「登り直しが短くなる」）
  - 区切りがないので、何時間でも続けられる。いつやめても損をしない

### 6つの要素が一つにかみ合う形
| 要素 | このゲームでは | プレイヤーがすること |
|---|---|---|
| タワーディフェンス | 敵は**パックそのもの**。道を上から下へ進む。下まで行かれると開けそこねる | 道ばたに置いて迎え撃つ |
| カードパック開封 | 倒す＝開封。封が硬いほど中身がよい | 硬いパックを割れる布陣を作る |
| キャラ収集 | 開けて出たキャラは、そのまま手持ちと図鑑に入る | 集めて、次に置くキャラを選ぶ |
| オートバトル | 置いたキャラは自動で撃つ。プレイヤーは撃たない | どこに何を置くかだけを考える |
| ストラテジー | 置く場所、壁の場所、連鎖の起こし方、どの強さのパックを呼ぶか | 組み方で突破する。お金や待ち時間では突破しない |
| インクリメンタル | 開封の数が桁で伸びる。1個ずつ → まとめて → 自動 → 束（1体が100個分、1万個分のパック） | 開けるしくみそのものを強くする |

ひとまとめに言うと「開けた中身が次に開けるための武器になる」。開封、撃破、収集、編成が一つの輪になっている。

### 組み込む仕掛け
- **レンガの壁（24）**：重複とハズレはレンガになる。レンガは道ぞいの壁に積まれ、パックの足を遅くする（撃たれる時間が長くなる）。壁は、隣に立っている**同じ色のキャラを強くする**（提案）。重複が「壁」と「強化」の両方になるので、引きが悪くても無駄にならない。どこに積むかは置き場所と同じ戦略になる
- **連鎖開封（33）**：パックが開くと、封のかけらが飛び散って周りのパックの封を削る。群れが固まっているところで硬いパックを割ると、まとめて開く。壁で群れを詰まらせて連鎖を狙う、というように、壁と連鎖が一つの作戦になる
- **強いパックを呼ぶ**：流れの強さはプレイヤーが上げ下げできる。硬いパックほど中身がよい。どれだけ欲張るかは、お金ではなく自分の布陣の腕で決める（「開発チーム.md」の観点：射幸性を、課金なしで気持ちよさに変える形）

### 「中身が味方になるか、敵として飛び出すか」の判断
**最初からは入れない。転生の2層め以降のルールとして、形を変えて入れる（提案）。**

理由
1. 「せっかく出たレアが敵になって失う」は、課金なしでも嫌な外れ方になる。重複をレンガにして「外れても損しない」形にしたのと逆を向く
2. 最初の数分は「倒して開けて置く」だけにしたい（市場調査の提案3：要素は段階的に開ける）。どちらになるかの判断が加わると、縦の小さな画面で起きていることが読みにくくなる
3. ただし「出てきたものが暴れる」は見せ場になる。そこで、**飛び出したキャラは一度だけ敵として暴れ、倒すと必ず仲間になる**形にする（失わない。倒すまでが少し遠いだけ）。暴れるのはレアだけにすれば、「暴れた＝いいものが出た」の合図にもなる

この形でよいかは、02 プリプロダクションとプロトタイプで確かめる。

## 売り（3つまで）
1. **倒すことが開けること**。敵のパックの封を割った瞬間に中身が飛び出し、そのまま次の戦力になる。開封を見てから編成する、という切れ目がない
2. **外れが壁になる**。重複とハズレはレンガになって道に積まれ、同じ色のキャラを強くする。引きの悪さが布陣の工夫に変わる
3. **待たない・払わない・それでも開ける手が止まらない**。スタミナ、待ち時間、日ごとの回数制限はない。開封の数が桁で増えていき、増えるほどまとめて速く開けられ、レアだけが大きく光る（市場調査の提案1）

## 遊ぶ人と場所
- **遊ぶ人**：まずオーナー本人。そのうえで、数字が桁で伸びるのが好きで、パックを開ける一瞬が好きで、組み方を考えるのも好きな人。片手で、空き時間にも、長い時間にも遊ぶ
- **プラットフォーム**：iPhone のブラウザ（Safari）。縦持ち・片手。1人用・オフライン・課金なし・保存は端末内（既定）。ホーム画面に置くWebアプリとして使うのを想定する（届け方は 02 で決める）
- **1回の遊ぶ時間／クリアまで**：1回は数分〜何時間でも。区切りはなく、いつやめてもよい。終わり（エンディング）を置くかは未決。置くなら、MVPは転生1層を取り切るまで（見積もり：数時間〜十数時間）、理想の形は全部の層を取り切るまで（見積もり：数十時間以上）

### 要素を開ける順番（提案）
最初の数分は「倒して開けて置く」だけ（市場調査の提案3）。

| いつ（見積もり） | 開く要素 |
|---|---|
| 最初の数分 | 道1本、パック1種、キャラを置く、自動で撃つ |
| 10分前後 | 重複がレンガになる、壁 |
| 20〜30分 | 連鎖開封、パックの強さを呼ぶ |
| 30〜60分 | まとめて開ける、開封の速さを上げる、自動で置き直す |
| 最初の転生 | 刷り直し。新しい道とルールが1つ加わる |
| 2層め以降 | 道の分かれ道、空を飛ぶパック、レアが飛び出して暴れる、束（1体が多数のパック）など。層ごとにTDのルールが増える（市場調査 3） |

### 入れないもの（市場調査の提案2）
- スタミナ、待ち時間、日ごとの回数制限
- 課金、広告
- 転生のあとの手作業の買い直し：自動化を早めに渡す（市場調査 3：嫌われる点）

### 開封の量が増えたときの見せ方（市場調査 4）
- まとめて：1個ずつ → 10個 → 100個をいっぺんに
- 速く：割れる演出を短くしていく。プレイヤーが選べる
- 自動で：手で触らなくても開き続ける
- レアだけ大きく：ふつうの中身は数字と小さな光でまとめ、レアだけ画面の中央で大きく見せる
- 留守のあいだ：ブラウザを閉じているあいだは計算が止まるので、開き直したときに経過時間からまとめて計算し、「留守のあいだに開けた分」をまとめて見せる（市場調査 5：推測、tech で確かめる）。留守のあいだの進み具合を、遊んでいるときと比べてどのくらいにするかは未決

## 見た目と音の第一印象
3案。推すのは案1。

1. **封蝋（ふうろう）の手紙が歩く国**（推す）
   - 封蝋で閉じた封筒やパックが、小さな足でとことこ道を歩いてくる。封蝋の厚さと色で硬さとレア度がひと目でわかる（薄い赤 → 厚い金、など）。割れると蝋のかけらが散り、そのかけらが周りの封を削る（連鎖が絵で説明できる）
   - 出てくるキャラは、切り紙や押し花のような平たい紙の住人。レンガは折りたたんだ厚紙で、積むと壁になる
   - 色：生成りの紙の地に、濃い色の蝋。小さな画面でも形と色で見分けられる
   - 音：紙のこすれ、蝋がぱきっと割れる音、小さな鐘。連鎖の数に合わせて音が上がっていく
   - 推す理由：「封の硬さ」「割れる」「かけらで連鎖」「重複が紙のレンガ」が、一つの素材（紙と蝋）で全部説明できる
2. **お菓子の袋の行列**
   - 包み紙の袋が行進してくる。中からお菓子の住人が出る。重複は角砂糖のレンガ
   - 明るく親しみやすいが、袋の硬さを見た目で表しにくい。アイデア出し16と近い
3. **星くずの袋が降る夜空**
   - 道は夜空の川。星の袋が流れてきて、割れると星座の住人が出る。重複は星のかけらの壁
   - きれいで「レアだけ大きく光る」が映えるが、暗い画面に小さな物が多いと縦の画面で読みにくくなるおそれがある

どの案も、既存の作品の名前、キャラ、絵柄には寄せない。キービジュアルを作るなら `game-art-concept` に頼む（プロデューサーの判断）。

## 似た作品との違い
市場調査 1・2 から。遊びの言葉で書く。

- **放置のタワーディフェンス**（市場調査 1）は、敵を倒して得たお金で塔を強くする。このゲームでは、**倒した敵そのものが次の塔になる**。強くするのはお金ではなく、開けた中身と、その置き方
- **カードを集めて戦うタワーディフェンス**（市場調査 1）は、戦う前にパックを開けて編成する。このゲームでは、**戦っている最中に開けて、その場で置き直す**。開封と戦闘のあいだに切れ目がない
- **パックの中身がそのまま選択になる作品**（市場調査 4）と同じく、中身がすぐ選択になる。違うのは、外れも重複も**壁として盤面に残る**こと
- **開封そのものを楽しむ作品**（市場調査 4）では、数が増えると開けるのが遅く面倒になるという声がある。このゲームでは、**開けるしくみを強くすることがインクリメンタルの本体**なので、数が増えるほど速く、まとめて、自動で開けられる
- 6要素を全部持つ名の知れた作品は、調べた範囲では見つかっていない（市場調査の結論。日本・中国のアプリは十分に見ていない）

## リスク
- **盛りすぎでわかりにくい**（市場調査の提案3）：6要素に、壁と連鎖が加わる。→ 要素を段階的に開ける。最初の数分は3つの動詞（開ける・置く・見る）だけにする
- **縦の小さな画面で読めない**：パックの群れ、かけら、キャラ、壁、数字が重なる。→ 封の厚さと色でひと目でわかる絵にする。数字はまとめる。iPhone の縦持ちで読めて押せるかを、プロトタイプで最初に確かめる
- **桁のインフレが破綻する**：開封数、パックの硬さ、キャラの強さ、レンガの数の4つが同時に伸びる。費用は指数・生産は線形で、後半の転生が弱く感じられるおそれ（市場調査 3）。→ 03 で `game-design-economy`・`game-spec-balance` が曲線を作る。JS の数の上限は約1e308なので、大きな数の扱いを 02 で決める（市場調査 5）
- **取り切ったあとの退屈**（市場調査 2）：層ごとにルールが増える転生で延ばす。それでも尽きたあとをどうするかは未決（終わりを置くか）
- **運の偏りで負ける**（市場調査 2）：重複のレンガで外れの損を消す。封の強さごとに、何が出るかの割合を見せるかは 03 で決める
- **放置と操作の釣り合い**：留守のあいだに進みすぎると、遊んでいるときの置き方の意味が薄れる。少なすぎると「何時間でも」の長い遊びと合わない
- **iPhone のブラウザの保存と音**（市場調査 5）：Safari の保存領域の扱いは報告が食い違う。iOS 26 以降のホーム画面のWebアプリで Web Audio が鳴らない報告がある。振動は使えない。→ 書き出し・読み込みのバックアップを必須にする。保存と音は 02 で最初に確かめる
- **見た目で埋もれる**（市場調査の提案3。"idler" タグの作品数が急に増えて、似た作品が多いと報じられている：市場調査 1）：封蝋の案のように、仕掛けがそのまま絵になる見た目を選ぶ
