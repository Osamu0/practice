書いた人：game-preprod-art（2026-11-18）。初版。
もとにしたもの：`01_企画/企画書.md`、`02_プリプロ/デザインの柱.md`、`進行表.md`、`開発チーム.md`。`02_プリプロ/技術選定.md` はこの時点でまだ無い（同時に作業中）。描き方の前提（コードで描く・ベクターで描く）は技術選定と食い違ったら直す。

このガイドの一番の決まり（柱3から）：**部品・規則・次の1手の印は、色を抜いても形で読み分けられること。色は2番目の手がかり。**

## 1. 方向の比較：第一案と対案（決めるのはオーナー）

### 第一案 A「帳面の谷」：生成りの紙と墨の線（企画書の提案）
生成りの紙の地に、細い墨の主線と少ない色。手で描いた帳面をめくっているような画面。部品は木・縄・真鍮・石の手ざわりを、平らな色と1〜2本の線で見せる。先祖の跡は褪せた色とひびで「古さ」が分かる。

### 対案 B「青焼きの工房」：濃い藍の地に白い線
設計図の青焼きのような、濃い藍の地に白い細線。部品は白線の図解に素材の色を小さく差す。工房と設計図の主題を前に出し、画面は暗い。

### 比べる
| 観点 | A 帳面の谷（紙と墨） | B 青焼きの工房（藍と白線） |
|---|---|---|
| 企画との合い | 「帳面」「年表」「墓」「谷に歴史が積もる」の温かみと、年表のおかしみに合う | 「設計図」「発明」に強く合う。墓・年表の情緒は出しにくい |
| 小さな画面の読みやすさ | 明るい地に墨の線で、昼の屋外でも読みやすい。夜の暗い車内ではまぶしい | 暗い地に白線で、夜は目にやさしい。昼の屋外では映り込みで沈みやすい |
| 危険の色の目立ち方 | 朱が紙の上でよく立つ（コントラスト約5:1） | 朱は暗い地で光るが、白線と競って画面がうるさくなりやすい |
| 電池（有機ELの端末） | 明るい地なので不利 | 暗い地なので有利 |
| 先祖の跡（古び） | 褪せ・ひび・紙の染みで自然に出せる | 古びの表現が「線が薄くなる」だけになりやすい |
| コードで作れるか | 線と平らな色と紙の地の質感（ノイズ）で作れる | 線だけで作れるので、Aよりさらに作りやすい |
| 外部のイラストとのなじみ | 手描きの絵と混ぜやすい | 手描きの絵と混ぜると浮きやすい |
| リスク | 地の色が特定の土地柄（和）に寄って見えやすい。土地柄が未決 | 画面が冷たく、「一族の物語」より「パズル」に見える |

アートの意見：**A を勧める**。柱1（継ぐのは考える材料）と企画の「谷に歴史が積もる」手ざわりに合い、昼の屋外の読みやすさも上。Bのよさは、A の中で**帳面の設計図を開いた画面だけ**を青焼き風（藍の地に白線）にすると取り込める（混ぜ案。採るかはオーナー）。暗い画面が欲しいなら、Aの「夜の紙」（下の 3.4）を設定で選べる形も案として出す。

以下は **A を前提に書く**。B に決まったら、色（3.3）を差し替え、形・数値・音・UIはそのまま使う。

## 2. スタイル（言葉で決める）

### 2.1 使う言葉／使わない言葉（対）
| 使う | 使わない |
|---|---|
| 手で描いた、図解のような（どこがつながっているか見える） | 写実の、絵画のような描き込み |
| 細い墨の主線、線の太さにわずかな揺らぎ | 太い黒縁の線、均一すぎる機械の線 |
| 平らな色、紙の地を残す余白 | グラデーション、光沢、発光 |
| 素材の手ざわり（木目1〜2本、縄のより、真鍮の照り1本、石の欠け） | 金属の質感表現、ハイライトの多用、細かいテクスチャ |
| 静か、余白、一画面に要るものだけ | にぎやか、詰め込み、飾りの模様 |
| 古びる（褪せ、ひび、紙の染み） | 汚し（泥・血・汚れのテクスチャ） |
| 少しのおかしみ（転ぶ、飛ばされる、煤ける） | 暗すぎる、グロテスク、流血 |
| 止まった絵として読める（1手ごとに止まる） | 常に揺れる・ちらつく画面 |
| どこの国とも決めない職人の道具と服（前掛け、布の帽子、革の手袋） | 特定の時代・国の衣装や建物の写し |

既存の特定の作品の絵柄・キャラ・ロゴは写さない。参考にするのは「線画に平らな色」「図解」「木版のような単純化」といった一般の技法の言葉まで。

### 2.2 形の言葉（何がどの形か）
| もの | 形 | ねらい |
|---|---|---|
| 当主 | 丸みのある縦長、2頭身半。頭が大きく、顔の向きが分かる。明るい塗り＋藍 | 盤面のどこにいても一番に目に入る |
| 部品 | 幾何の形（四角、丸、直線）。つなぎ目は縁の小さな丸（つなぎ点）で必ず描く | 組んだ道具が「どの部品をどこでつないだか」形で読める |
| 発明品 | 部品の絵をそのまま組んだ見た目（企画書のとおり）。別の絵に描き替えない | 絵の数が部品の数で済む。設計図と見た目が一致する |
| 敵（谷の災いが生んだ物） | 墨のベタ塗り、左右非対称、縁がにじむ。目は紙の色で2つ | 当主・部品と塗りの明るさで逆になり、色なしでも分かれる |
| 災いの主 | 3×3マス以上の大きな墨のにじみ。代ごとに盤面ににじみが広がる | 「災いが進む」が絵で見える |
| 先祖の跡（墓、遺品、据えた仕掛け） | 低く横長、ひび、色が褪せる。家の印（下の 2.4）が付く | 「うちの一族のもの」と一目で分かる |
| 地形 | 横の線の重なり（地層）、崖は縦のかすれ線。中は塗らずに紙の地 | 背景を静かにして、上に乗る物を立てる |
| UI | 紙片・札・判子の形。四角に近く、角は小さく丸める | 帳面の世界の中の道具に見える |

### 2.3 線・質感・光
- 線：主線は墨色。太さに ±15% の揺らぎ。揺らぎは物ごとに種（シード）で決め、毎フレーム変えない（ちらつかない）
- 質感：紙の地に薄いノイズ（繊維）。強さは地の色の明るさの ±3% まで。盤面のマスの上には繊維を出さない（印が読みにくくなる）
- 光：光源は左上に1つ、固定。影は右下に紙の上の薄い落ち影（ずらし 2px、墨色の不透明度 18%）。動く光・時間帯の光は使わない
- 塗り：1つの物に平らな色は2色まで（地の色＋影色1つ）。影色は地の色の明るさを −12%

### 2.4 一族と継承の見せ方
- **家の印**：一族ごとに、丸・菱・四角の枠の中に単純な図形（線3本まで）を組んだ印をコードで作る。墓、遺品、据えた仕掛け、帳面の表紙に付ける。実在の家紋・団体の印は写さない
- **肖像（顔の部品の組み合わせ）**：輪郭4、目6、眉4、鼻3、口4、髪型8、髪色8、肌の色5。子は親の部品の一部を受け継ぎ、少し変わる（どれをどれだけ継ぐかは仕様）。部品の組み合わせなのでコードで並べられ、「どこか親に似ている」が作れる
- **癖の見た目**：癖ごとに小さな印（16px）を1つ。肖像の横と帳面に出す。体つきで癖を表すことはしない（誤解とステレオタイプを避ける）
- **古びの段**：新しい／傷み／壊れかけ の3段。ひびの本数（0／1／2本）と色の褪せ（彩度 −0%／−25%／−50%）の両方で見せる。色だけにしない

## 4. 画面の読みやすさと、制作の数値

### 4.1 画面の大きさ（縦持ち）
- 基準の大きさ：**幅 360 × 高さ 640（CSS px）**。これより小さい端末は想定しない（最小の幅 360）
- 幅が広い端末：盤面と作業台は真ん中に置き、左右は紙の地。拡大はしない（マスは最大 56px まで）
- 縦が長い端末：増えた高さは**画面の上（盤面の上）に足す**。親指の届く下側の配置は動かさない
- 描くときは端末の画素の密度（devicePixelRatio、最大 3）に合わせ、絵がぼけないようにする
- PC：縦長の枠（360〜430 幅）を画面の真ん中に出す。操作はマウスで同じ

### 4.2 画面の割り付け（基準 360×640、挑む画面）
| 帯 | 上からの位置 | 高さ | 中身 |
|---|---|---|---|
| 上の帯 | 0〜44 | 44 | 代・年・掟の札（見るだけ。ボタンは置かない） |
| 盤面 | 52〜388 | 336 | 7×7 マス（48px） |
| 説明の帯 | 392〜436 | 44 | 選んだもの・次の1手で起きることを1行で |
| 手の棚 | 440〜560 | 120 | 部品・道具・手の選択肢（下の数値） |
| 親指の帯 | 568〜632 | 64 | 確定（大）、取り消し、1手送り・早送り、メニュー |

組む画面も同じ割り付けで、盤面の場所に作業台、手の棚に部品の棚を出す。

| 肖像 | 家系図 **56×56**、継ぐ画面 **160×160**（描く基準 160） | |
| 癖・掟の印 | **16px**（札の中）、説明の画面では 32px | |
| 1画面で盤面に同時に出す印 | 当主の次の1手＋道具の動き＋敵の次の手 **まで** | 先の手の予測（2手以上先）は出さない |

### 4.4 動き（コマ数と時間）
ターン制なので、動きの多くは位置の補間（からくり人形のように、止まって・動いて・止まる）。手描きのコマのアニメは少なくする。
| 動き | コマ数／時間 | メモ |
|---|---|---|
| 1手の再生（1段ごと：当主→道具・物→敵・仕掛け） | 標準 **300ms**／段、早送り **100ms**／段 | 段の間に **120ms** 止める（何が何を押したか目で追える） |
| 1手送り | タップで1段ずつ | 柱3 |
| 当主 待機 | **2コマ**、1周 1.2 秒 | 呼吸の上下 1px だけ |
| 当主 歩く | **4コマ**、12fps | マス1つ＝300ms |
| 当主 使う・押す | **3コマ** | |
| 当主 倒れる（死） | **4コマ**＋紙の上に墨が少しにじむ | 血は描かない。少しおかしみ |
| 敵 待機 | **2コマ**、にじみの縁がゆれる | 揺れは止まった絵としても読める範囲 |
| 敵 動く | **3コマ** | |
| 部品：ばね | **3コマ**（縮む・中・伸びる） | |
| 部品：火 | **3コマ** ループ、8fps | |
| 落ちる | 加速して落ちる（ease-in）、着くと 2px つぶれて戻る | 規則ごとに動きの癖を変え、動きでも規則が分かる |
| 弾む | 弧を描く、頂点で 1 拍ゆっくり | |
| 引っぱる | 一定の速さ、縄がぴんと張る線 | |
| 燃え移る | 隣のマスに炎が「ぽっ」と出る（150ms） | |
| 点線の印の流れ | 1周 1.2 秒 | 「動きを減らす」設定で止める |
| 画面の揺れ | 原則なし。大きな崩れだけ 2px・200ms | 「動きを減らす」で 0 |
| 何も動いていないとき | 描き直さない | 電池（tech-performance と合わせる） |

### 4.5 読みやすさの決め
- 盤面の上に文字は置かない。数字を読まないと分からない表示はしない（重さは黒丸の数、傷みはひびの本数）
- 説明の帯は1行（全角 20 字まで）。それより長い説明は帳面を開いて読む
- 指で隠れる問題：ドラッグ中の部品は指の **上 56px** に浮かせて描き、置く先のマスを枠 3px で示す
- 背景（地形）は薄墨と紙の地だけにして、上に乗る物（当主・部品・敵・印）より必ず弱くする
- 掟の効果（雨の線、風の流線）は盤面の上で不透明度 25% まで。印より強くしない

## 5. UIの方向

- 形：紙片・札・判子。角の丸みは 4px。ボタンは白練の地に墨の縁 2px、押すと 1px 下がって落ち影が消える
- 押せない：薄墨＋斜線（灰色にするだけにしない）
- 大きさ：タップできる物はすべて **48×48px 以上**。主ボタン（確定）は **高さ 64px・幅 160px 以上**、親指の帯に置く
- 置き場所：ボタンは画面の下半分（基準で y 392 より下）。上の帯は見るだけ。盤面のマスのタップは例外だが、盤面の上の段（y 52〜150 あたり）は片手の親指が届きにくい。行き先を棚の選択肢からも選べる形を UX に提案。左手・右手の切り替え（左右反転）も UX に提案
- 確定の一押し：手を選ぶ→説明の帯に結果が出る→確定、の2段。危険な手は確定の札が朱の縁になり「！」が付く
- 字：本文・UI はゴシック体、帳面・年表・掟の名前は明朝体（書き物の感じ）。大きさは本文 **16px**、補足 **14px**、最小 **12px**（小印の中の文字だけ）、見出し **20px**。行の高さ 1.6。数字は幅のそろった字形
- フォントは自由に使えるライセンスのものから選ぶ（選ぶのは art-ui、条件の確認はオーナー）。日本語のフォントは大きいので、使う字だけに絞って読み込む（技術選定と合わせる）
- 画面の情報量：1画面の文字は帳面の外では3行まで。帳面・年表・図鑑は読むための画面なので、紙のページとして文字を多く置いてよい
- 帳面：ページをめくる見た目（横に送る）。ページの数に限りがあることを、空きページの数で見せる

## 6. 音の方向（声なし）

### 6.1 全体の決め
- 音がなくても遊べる（電車で音を消して遊ぶ前提）。音の情報は、すべて絵でも出す。音は2番目の手がかり
- 楽器：木の打楽器（木琴のような柔らかい音）、撥弦（指ではじく弦）、木管の笛、櫛の歯をはじく小箱の音（オルゴールのような）、低い弓の弦を少し。電子音の派手な音は使わない
- 質感：部屋の中で鳴っている近い音。残響は短め（小さな木の工房）。谷の場面だけ少し広い
- **一族の旋律**：8音の短い旋律を年代記の始めに1つ決め、代が替わるたびに1か所を変える（1音、楽器、テンポのどれか）。当主の癖で少し変わる（例：せっかち→少し速い）。どう変えるかの規則は audio-composer と決める
- 音の大きさの目安：全体 −16 LUFS、BGM は効果音より 6dB ほど下。効果音は短く、頭の無音 10ms 以下

### 6.2 場面ごと
| 場面 | テンポ（BPM） | 楽器・音 | 感じ |
|---|---|---|---|
| 工房（組む・予行） | 72〜84 | 撥弦と木琴、薄く。木槌・ばねの音が主役 | 落ち着いて考えられる |
| 谷の地図 | 曲は薄く 60〜70、環境音が中心 | 風、水、遠くの鳥。代が進むと墓や仕掛けの小さな音が増える | さびしい谷が、にぎやかになる |
| 挑む（課題） | 90〜100 | 木の打楽器で拍をはっきり、笛の短い句 | 一手ずつ前へ進む。1手の再生と拍は合わせない（待たせない） |
| 災いの主 | 108〜120 | 低い弓の弦、太鼓のような低い打音 | 重い、でも暗すぎない |
| 遺す・墓 | 56〜64 | 一族の旋律を小箱の音でひとつだけ | 託す。悲しすぎない |
| 継ぐ・代替わり | 短い節（4〜8小節） | 一族の旋律の変奏 | 「同じ家の、新しい一代」 |
| 年表・図鑑 | 曲なし、または工房の曲を小さく | ページをめくる紙の音 | 読む |

### 6.3 効果音（規則ごとに音を分ける）
| きっかけ | 音の質感 |
|---|---|
| 部品を持つ・置く | 木の「こと」、置くと少し低い「こつ」 |
| つなぐ | 縄を結ぶ短いきしみ、金具の「かち」 |
| 確定 | 木槌の「こん」1回 |
| 取り消し | 紙をめくる短い音 |
| 重さ・落ちる | 低い木の「ごとっ」、落ちる前に短い風切り |
| 弾む | ばねの「びよん」、ピッチが上がる |
| 燃える | ぱちぱちの雑音、燃え移るたびに「ぽっ」 |
| 引っぱる | 縄がぴんと張るきしみ |
| 課題が解けた | 短い上がる3音（木琴）。仕掛けが動いた瞬間の「かちり」と重ねる |
| 危険の手を選んだ | 低い2音、短く |
| 死 | 一族の旋律の最初の2音だけ、少しずれて |

## 7. この環境で作れる範囲と、外部に頼むと良くなる範囲（依頼一覧の材料、決めはオーナー）

| 種類 | この環境で作れる（頼まないとき） | 外部に頼むと良くなる | アートの意見 |
|---|---|---|---|
| 部品・地形・印・UI の絵 | 線と平らな色のベクター（SVG・コードで描く）で作れる。A のスタイルはこの作り方に向く | 墨の線の手ざわり（筆のかすれ） | **頼まない**でよい。数が多く、直しが多いので、コードのほうが速い |
| 肖像（顔の部品） | 単純な形の部品の組み合わせなら作れる | 手描きの部品にすると「親に似ている」の味が大きく増す | **候補（中）**。部品で頼めば、継承の仕組みにそのまま入る。仮はコードで作る |
| キービジュアル・タイトル画・代替わりの一枚絵 | 単純な構図の絵なら作れるが、絵の質は低い | 「谷と一族」の印象が一枚で伝わる。企画書のリスク8（画面1枚で違いが伝わるか）に効く | **候補（高、ただしアルファ以降でよい）** |
| 谷の地図の一枚絵（背景） | 線の重なりの地形で作れる | 手描きの谷にすると、墓・仕掛けが積もる場所としての情緒が増す | **候補（低〜中）**。上に乗る物の読みやすさを壊さないことが条件 |
| BGM | 合成音の曲と短い節。一族の旋律の変奏は規則で鳴らせる（コードで作る利点） | 生の楽器（撥弦、木管）の曲の質。場面の曲 5〜6 曲 | **候補（中〜高）**。変奏の仕組みはこちらで作り、楽器ごとの音（ステム）と旋律の材料を頼む形が合う |
| 効果音 | 合成した効果音（ばね、木の打音は合成でもある程度出る） | 木・縄・真鍮・石の生の録音。「部品の手ざわり」は企画の見どころ | **候補（高）**。部品の手ざわりは録音の差が大きい。仮は合成で作る |
| アニメーション | 位置の補間と、2〜4コマの単純なコマ | 当主の手描きのコマ | **頼まない**でよい。ターン制で補間が主 |
| フォント | 自由に使えるフォントから選ぶ | — | **選ぶ**（依頼ではない） |
| 声 | なし | — | 頼まない（オーナーの決め：声なし） |

どれも、届くまでは本番と同じ大きさ・長さの仮のものをこの環境で作って先に進める（依頼書の決まり）。

## 8. 自分で見直したこと・確かめていないこと

- 見直した：柱3（片手・小さな画面・色に頼らない）に、色の表（3.2）、マスの大きさ（4.3）、ボタンの置き場所（5）で答えている。柱2（同じ組み方は同じ動き）に合わせ、線の揺らぎも毎フレーム変えない決めにした
- 確かめていない：この作業ではコードを動かしていない（見本の画面は作っていない）。コントラストは手計算の目安。実機での 48px のマスの押しやすさ、24px の部品の見分け、色覚の真似の確認は、04 プロトタイプで確かめる
- 色の見本・部品3点・挑む画面1枚の見本（スタイルの見本）は game-art-concept に作ってもらうとよい（プロデューサーの判断）
