# 計画（マイルストーン・作業の分け方・リスク・削る順番）：継ぎ手の工房（仮）

書いた人：game-preprod-producer（2026-11-18）。初版。
もとにしたもの：`進行表.md`、`開発チーム.md`、`01_企画/企画書.md`、`02_プリプロ/デザインの柱.md`、`02_プリプロ/技術選定.md`、`02_プリプロ/アートディレクション.md`、`02_プリプロ/スタイル見本/`（PNG 7枚）。
前提（オーナーの決め）：**期限なし・品質優先**。だから日付は書かない。マイルストーンは「順番」と「終わったと言える条件」で区切り、条件を満たすまで次へ進まない。時期は未決のまま。
「案」と書いたところは計画担当の提案で、オーナーの決めではない。

この計画の一番の決まり：**期限で切らない代わりに、条件で切る**。期限がないと、作り込みが終わらない・足したくなる、が一番の敵になる（リスク P1）。各マイルストーンに「ここで足すのをやめる」線を書いておく。


| # | マイルストーン | 部門 | 判定 | ひとことで | 時期 |

## 2. マイルストーンごとの中身と、終わったと言える条件

### M0 プリプロ完了（ゲート02）
中身：デザインの柱・コアループ・スコープ（済）、技術選定と最小の動く確認（済）、アートディレクションとスタイル見本（済）、この計画、依頼一覧の初版。
終わったと言える条件：
- [ ] `reference/02_preproduction.md` のゲート02の条件が全部ある
- [ ] 6章の「4つの文書の食い違い」の各行に「どこで決めるか」が書いてあり、ゲート02でしか決められないもの（見た目の方向 A/B）はオーナーが決めた
- [ ] 依頼一覧の各行に、オーナーが「頼む／頼まない／あとで決める（決める時期）」を決めた
- [ ] 監修（design-director、tech-director、audio-director）の「必ず直す」が0

### M1 仕様（ゲート03）
中身：**プロトの問い3つと縦切りに要るぶんを先に**仕様にする。全体の仕様は 03 で書くが、数（部品・癖・掟・敵・場所）の確定は M2 の結果を見てから直す前提にする。
最初に決める（これがないと M2 が作れない）：
- 規則5つの中身と、**同じマスで規則がぶつかったときの順番**（技術選定 R4、柱2）
- 作業台の基本の大きさと上限、癖で広がる量（6章 #3）
- 盤面の大きさとスクロールの有無（6章 #2）
- 試し場の置き方（6章 #4）、挑む画面で当主の行き先をどう選ぶか（6章 #6）
- 部品の系統と素材の対応（6章 #5）
- 縦切りの1場面の中身（下の M3 の案）
終わったと言える条件：
- [ ] 必須機能の仕様に受け入れ条件があり、仕様レビューの「必ず直す」が0
- [ ] 規則のぶつかる順番が表になっている（全部の規則の組み合わせに行がある）
- [ ] 6章の食い違いのうち「03で決める」ものが全部閉じている

### M2 プロト（04 前半）
中身：デザインの柱.md の問い3つを、それぞれ捨てる前提の別プロトで確かめる（問いが独立なので同時に作ってよい）。描き方は技術選定の構成（`src/core/` の決まりは守る。捨てても芯は持ち込めるように）。
| 問い | プロトの中身（デザインの柱.md より） | 「はい」の線（案。04 で直してよい） |
|---|---|---|
| Q1 組んで試すのが縦持ち片手で2〜4分で気持ちいいか | 作業台 4×4〜5×5、部品 8前後、規則3、課題1 | 初見の人の中央値が4分以内に解ける／置き間違いが1課題で2回以下／遊んだ後に「よし」「なるほど」に当たる反応が出る |
| Q2 親の設計図を子の癖と掟で組み直すのが「発見」になるか | 同じ課題を一代目・二代目で。死ぬ→遺す→継ぐを通す | 遊んだ人が一周を自分の言葉で説明できる／二代目で設計図を変えた／「もう一代やりたい」と言う人が過半 |
| Q3 違う原理の解き方が出て、万能の道具が出ないか | 規則5、部品 約12、課題の型3 | 各課題で違う原理の解き方が3つ以上／全課題を1つの道具で解けた人がいない |
終わったと言える条件：
- [ ] 問い3つに「はい」（「いいえ」のものは、仕掛けを変えるか捨てると決めた。同じ問いで3回直してだめなら 02 に戻す）
- [ ] **少なくとも Q1 はスマホの実機（オーナーの端末か、それに近い端末）で確かめた**。エミュレーションだけでは「はい」にしない（リスク P2）
- [ ] 実機の保存の長期試験（技術選定 R1：8日以上触らない）を**このときに始めておく**（結果は M3 までに）

### M3 縦切り（ゲートB、オーナー）
中身（2026-11-19 プロデューサーが決め。オーナーの条件「すぐ終わらないこと」）：**課題の場所5か所 × 三代**、寿命と隠居あり、掟2種・癖4種、通しで45〜60分が目安。一代目が組む→挑む→老いるか死ぬ→遺す、二代目が継ぐ→組み直す、三代目で祖父母の墓と失敗作が自分の癖と掟で効く瞬間まで（企画の売り1・2が両方見える長さ）。本番の見た目（B）・合成の仮の音・本番の UI で。二代では「先祖」が親1人だけになり、谷に歴史が積もる感じが出ないので三代にした。
- 規則5つ全部、部品 約10、癖 2〜3、掟 2、敵 1〜2種、墓と遺品、据えた仕掛けの傷み1段、年表の一文、帳面、書き出し・読み込み
- 入れない：年代記の終わり、解放、図鑑・家系図の画面（記録だけは取る）、災いの主
終わったと言える条件：
- [ ] プロトの問い3つに「はい」がそろっている（M2）
- [ ] 縦切りが**オーナーのスマホのブラウザで開ける**（届け方が決まっている。技術選定 R10）。起動方法とスクリーンショットがある
- [ ] 画面の数値がアートディレクションの 4.3 どおり（マス、ボタン、印の線）。白黒のスクリーンショットで意味が読み分けられる（アートの確かめ方）
- [ ] 実機で：ドラッグ直後のタップが効く（R8）、アドレスバーの出入りで下のボタンが隠れない（R9）、音が鳴る（R6）、書き出し→読み込みで元どおり
- [ ] 1手の再生（300ms×段＋120ms）を入れて、1課題が2〜4分に収まる（リスク P8）
- [ ] 監修（design-director、creative-director、art-director）の「必ず直す」が0
- [ ] オーナーが「この方向で作り込む」と言った
- [ ] ここで**MVPの数を再相談する**（進行表の決め「MVPで再相談」）。縦切りを作った手間から、MVP全体の量を見積もり直して、7章の削る順番の下限を確定する

### M4 開発開始（ゲート05）
中身：縦切りから本番の土台へ持ち込む（規則の芯 `src/core/` はそのまま、画面は作り直してよい）。
終わったと言える条件：
- [ ] 土台が起動し、`npm test`（規則の芯）と e2e が毎回流れる
- [ ] 決まった規則のテスト（指紋の固定値、記録からの作り直し、Node とブラウザの一致）が入っている（R4）
- [ ] 保存の版の扱い（移し替えるか、古い規則のまま続けるか）が決まった（R5）
- [ ] バックログが M5〜M7 に割り付いた。各タスクに3章の分け方のどれかの印がある

### M5 アルファ（ゲートC、オーナー）
中身：MVPの必須機能（デザインの柱.md のスコープの「必須」全部）と、数は**少なくとも7章の下限まで**。見た目・音・文は仮が残ってよい。
終わったと言える条件：
- [ ] スコープの「必須」が全部入っている（隠居は、オーナーの決めしだい）
- [ ] 年代記1本を、一代目から「鎮める」と「家が絶える」の両方の終わりまで、止まらずに通せる
- [ ] 年代記をまたぐ解放が少なくとも1段動く
- [ ] 致命のバグ（落ちる、保存が消える、進めない）が、わかっているものは全部バグ表にある
- [ ] 保存の大きさを、年代記1本ぶんで測った（R3）
- [ ] 遺品・仕掛けの積み上がりが上乗せになっていないかを、game-spec-balance が年代記を通して見た（リスク G4）
- [ ] オーナーが「この機能で出す」と言った（**ここで機能を確定。以降は足さない**）

### M6 ベータ（ゲート10）
中身：中身の確定、仮の資産を本番に差し替え、バグを潰し、遊び心地を詰める。新しい機能も中身も足さない。
終わったと言える条件：
- [ ] 中身の数が確定し、仮の資産がない（外部に頼んだものが届いていなければ、この環境で作った版を本番にすると決める。依頼一覧の「頼まない場合の代わり」）
- [ ] 致命0、重大は0か残す理由をオーナーに伝えた
- [ ] 初見テストで、最初の5分（デザインの柱.md の表）に大きな迷いがない
- [ ] 実機（iPhone の Safari と Android の Chrome の両方）で、5.2 の表に当たる確認を手でした（R6）
- [ ] 画面の文の最終の監修（story-dialogue-review）、音の釣り合い（audio-director）

### M7 リリース（ゲートD、オーナー）
終わったと言える条件：
- [ ] `reference/11_qa_release.md` のリリースの条件が全部（きれいな状態から同じビルド、自動テスト全部、致命・重大0、確認の否・わからない0、版番号・変更履歴・クレジット）
- [ ] 30分以上の連続プレイで重くならない、電池の減りを実機で見た（R7）
- [ ] 古い版の保存の扱いが決めどおりに動く（R5）
- [ ] フォント・外部に頼んだ素材の使える範囲とクレジットがそろった（オーナーが確かめる）
- [ ] オーナーが「出す」と言った

## 4. リスク表

起きやすさ・重さ：高／中／低。

| # | 起きること | 起きやすさ | 重さ | 先に打つ手 | 気づく合図 | 見る担当・いつ |
|---|---|---|---|---|---|---|
| **P1** | **期限がないので、作り込みと足したいものが止まらず、M5 に届かない**（品質優先がスコープの膨張に変わる） | 高 | 高 | マイルストーンを条件で切る。M5（ゲートC）で機能を確定し、以降は足さない。足したいものは「あれば」の表に積むだけにする。M3 で数を再相談 | 同じゲートの条件を2回続けて満たせない／「あれば」から必須へ移す話が出る／バックログが減らずに増える | プロデューサー、各ゲート |

## 5. 削る順番（スコープが溢れたとき）

「溢れた」と判断する合図（案）：同じゲートの条件を2回続けて満たせない、または M3 の見積もり直しで「必須」が品質を保ったまま作れないと分かったとき。削れないときはオーナーに相談（gates.md の戻り方）。

### 5.1 まず「あれば」を捨てる（MVPの後に回す順）
上から先に捨てる。重いのに一周に効かないものから。
1. 配偶者を選んで遺伝を組む、分家、家の技（仕組みが重く、釣り合いの確認が増える）
2. 掟30以上・掟の組み合わせの特別な時代、癖40以上
3. 地方を増やす（3〜4）、前の年代記の跡が遺跡で出る
4. 部品の系統8以上、規則10前後（解放の段を増やす）
5. 年表を絵巻で見返す、代替わりの演出（簡素な画面で足りる）
6. 決まった種（シード）で遊ぶ挑戦
7. 少ない部品で解く記録（図鑑の延長で安い。最後まで残す）
8. 一族の旋律の変奏は「あれば」だが、音の作りの芯に関わるので、捨てるなら1つの旋律の固定で残す

見せ方の上乗せ（表示「くっきり」、外部に頼む素材）は、上と別に、**頼まない場合の代わり**（依頼一覧）に戻すことで削る。

### 5.2 次に MVP の数を削る（デザインの柱.md の順と同じ）
**課題の場所 → 敵の種類 → 掟 → 癖 → 部品 → 規則**。規則は組み合わせのもとなので最後。どれも0にしない。
下限は案（03 の仕様と、M3 の見積もり直しで確定する）：
| 順 | もの | MVPの目安 | 下限（案） | 下げるときに守ること |
|---|---|---|---|---|
| 1 | 課題の場所 | 10〜15 | 8 | 課題の型6つが全部、少なくとも1か所ずつ残る |
| 2 | 敵の種類 | 約8＋主1 | 4＋主1 | 追い払う・守るの課題が成り立つ。動き方の規則が重ならない |
| 3 | 掟 | 約8 | 5 | 規則5つのそれぞれに効く掟が少なくとも1つ |
| 4 | 癖 | 約12 | 8 | 全部に長所と短所。子の候補2〜3人で同じ癖ばかりにならない |
| 5 | 部品 | 約20（5系統） | 14（各系統2以上） | 5系統は削らない |
| 6 | 規則 | 5 | 3（デザインの柱.md の案） | 最初の1時間で規則がひととおり出そろう流れを直す |

### 5.3 削らないもの（削るなら 01 企画に戻る話）
組む→試す→挑む→遺す→継ぐ→組み直すの一周、予行、次の1手の印、確定ボタン、課題ごとの自動保存、**保存の書き出し・読み込み**、墓と遺品、傷む仕掛け、災いの進み、年代記の終わり。
