# 機能仕様：保存（自動保存、再開、書き出し・読み込み）

書いた人：game-spec-writer（2026-11-18）。技術選定 4.3（localStorage の1つのキー、書き出しと同じ文字列、3つの照らし合わせ）を、この仕様の決めにした。
`開発チーム.md` の観点（game-sys-gameplay：保存の書き出し・読み込み）に合わせ、受け入れ条件を厚めにした。

- 目的（どの柱のためか）：
  - 柱3：すき間時間にやめても損がない（確定した手は全部残る）
  - 企画書リスク6・技術選定 R1：iPhone の Safari が端末内の保存を消すことがあるので、書き出しは必須
- プレイヤーから見た動き：保存のボタンはない。手を確定するたび、組むたび、画面の区切りごとに自動で残る。アプリを閉じて開き直すと、最後に確定したところから続く。メニューの「書き出す」で、年代記全部を文字（コピー）かファイルにでき、「読み込む」で戻せる。最後に書き出してから日がたつと、促しが出る

---

## 1. いつ保存するか（計画.md 6章 #8 の決め）

技術選定のとおり「手を確定するたび・課題ごと」に加え、組む操作と画面の区切りでも書く。

| きっかけ | 保存する |
|---|---|
| 挑むで手を確定した（計算が終わった時点。再生の前） | ○ |
| 課題の終わり（結果の選び終え、引き返す） | ○ |
| 作業台の操作1つ（置く、動かす、向き、外す、設計図を開く、組み上げる） | ○ |
| 工房で直す・ばらす | ○ |
| 遺すで書き終える／継ぐで確定／代替わりの終わり | ○ |
| 年代記の終わり、解放 | ○ |
| 設定を変えた | ○ |
| 試し場で動かす、手を選ぶ（確定の前）、ひとつ戻すの履歴、遺す・継ぐ・結果の途中の選び | ×（保存しない） |

## 2. 再開（開き直したとき）
| 最後に保存したところ | 開き直したときの画面 |
|---|---|
| 挑むの手の確定 | 挑むの、次の手を選ぶところ（その手の再生は飛ばした状態）。**課題の途中から始まる** |
| 作業台の操作 | 作業台（同じ中身）。ひとつ戻すの履歴はない |
| 結果・遺す・継ぐの画面に入った | その画面の最初から（途中の選びは消える。引く物はシードで決まるので同じ） |
| そのほか | 谷の地図 |

## 3. 何を保存するか
1つの文字列（書き出しと同じ形）に、次を全部入れる。

| 中身 | 説明 |
|---|---|
| 形の版 | 書き出しの頭（`YK1` など） |
| 規則の版 | 規則の芯の版。読み込みで照らす |
| 年代記をまたいで残るもの | 解放の段、過去の年代記の年表・図鑑・家系図 |
| 今の年代記のシード | 乱数の流れのもと |
| 今の状態 | 代、谷暦、災いの段、当主（名前、癖、肖像）、掟、帳面、この代の設計図、持ち物・棚、作業台の中身、谷の場所ごとの物（墓と遺品、仕掛け、置いたままの道具）、物の番号の次の値、今の画面（挑む中なら、その盤面と手数） |
| 記録 | **この代の始まりの状態の写し ＋ この代の操作の記録**（挑むの手、作業台の操作、結果・遺す・継ぐの選び）。前の代の操作の記録は、年表・図鑑の要約に置きかえてよい（技術選定 R3。切り方の細かい決めは 05） |
| 指紋 | 今の状態の指紋 |

- 設定（動きを減らす、左右反転など）も入れる
- 個人の情報（名前、端末の情報）は入れない

## 4. 端末内の保存
- localStorage の1つのキーに、3章の文字列を入れる（技術選定 4.3）
- 起動したときに `navigator.storage.persist()` を頼む。結果には頼らない（技術選定 R2）
- 書き込みに失敗したら（上限など）：ゲームは止めず、そのまま遊べる。「端末に保存できなかった。書き出してください」と出し、書き出すの札を出す。次の保存のきっかけで書き直しを試す
- 起動したとき、端末内の保存が読めない（3つの照らし合わせのどれかが合わない）ときは、**黙って新しく始めない**。「保存が読めない」と理由を出し、選べるのは①読めない文字をそのまま書き出す（あとで直せるように）、②読み込む（前の書き出しから）、③新しく始める（確かめの一押しのあと。端末内の古い文字は消える）

## 5. 書き出し
- メニューの「書き出す」から。2つの道：
  - **文字をコピー**（主）：文字列をクリップボードに入れる。入れられないときは、選んでコピーできる文字の欄を出す
  - **ファイル**（従）：テキストファイル（`.txt`）をダウンロードする。ファイル名は**英数字だけ**（技術選定 4.3）。案：`yk_save_g<代>_y<谷暦>.txt`
- 書き出した日時を保存の中に記録する（画面側の時計を使う。規則の芯の外）
- **最後に書き出してからの日数**を、タイトルとメニューに出す。`save.exportNudgeDays` 日以上たったら、谷の地図に促しの札を出す（技術選定 R1 の7日の消去より前に）。代替わりの画面にも「書き出す」の札を出す（案）

## 6. 読み込み
- メニューの「読み込む」から。文字を貼る欄か、ファイルを選ぶ
- 照らし合わせ（技術選定 4.3）：①頭の版、②指紋、③この代の始まりの写しと記録から作り直した状態の指紋
- 3つとも合ったら：読み込む年代記の要約（代、谷暦、当主の名前、最後に書き出した日）と、今の年代記の要約を並べて出し、「今の年代記は消える」と書いた確かめの一押しで置きかえる。確かめの画面に「今の年代記を先に書き出す」の札を出す
- どれかが合わないとき：読み込まず、今の年代記は**何も変えない**。どれが合わなかったかで理由を分けて出す（形が違う・途中で切れている／文字が欠けたか書き換えられた／規則の版が違う）
- 規則の版が違う書き出しをどう扱うか（移し替えるか、古い規則のまま続けるか）は 05 で決める（技術選定 R5。未決）。決まるまでは読み込みを断る

## 7. 状態と遷移
| 今の状態 | きっかけ | 次の状態 |
|---|---|---|
| 起動 | 端末内の保存が読めた | 2章の再開の画面 |
| 起動 | 端末内の保存がない | タイトル（新しく始める） |
| 起動 | 端末内の保存が読めない | 保存が読めない画面（4章の①②③） |
| メニュー | 書き出す | 書き出し（コピー／ファイル）→ メニュー |
| メニュー | 読み込む → 照らし合わせが全部合う → 確かめ | 読み込んだ年代記の再開の画面 |
| メニュー | 読み込む → どれかが合わない | 理由を出してメニュー（今の年代記はそのまま） |

## 8. 数値（`パラメータの名前.md`）
`save.exportNudgeDays`。保存の大きさの上限、記録の切り方は 05（game-prod-architect、技術選定 R3）。

## 9. 例外・境界
- **0**：まだ何もしていない（一代目の最初）ときも書き出せる
- **最大**：保存の大きさは M5 で年代記1本ぶんを測る（計画.md M5）。上限に近づいたときの移し先（IndexedDB）は 05
- **同時**：同じ端末で2つのタブで開いたとき、あとから書いた方が残る（MVPでは防がない。未決）
- **中断**：保存の書き込みの途中で閉じても、前の保存が壊れないようにする（新しい文字を書けたときだけ置きかえる）
- **死亡**：死んだ手の確定で、墓・遺品・年表の一文まで保存される
- **ポーズ**：時間で進むものはないので、閉じている間に何も変わらない

## 10. 演出と音のきっかけ
- 自動保存は見せない（音も出さない）。書き出し・読み込みが終わったら、紙をめくる短い音と1行の知らせ（案）
