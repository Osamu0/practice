# プレイテスト記録

## Q1 組んで試す（1回目、2026-11-19、game-proto-playtester。AIの操作、Chromium 390×844 タッチ）

問いへの答え：
| 問い | 答え |
|---|---|
| 親指だけで組み、予行で外れ、理由が分かって直し、解くまで行けるか | はい（AIの操作で） |
| 外れた理由が分かるか | はい（条件つき：本番で道具だけ落ちると出口がない） |
| 2〜4分に収まるか | 分からない（人で確かめる要あり）。手数は最短約21タップ、外れて直すと40〜60タップの推測 |
| 指で部品が隠れて置き間違えないか | 分からない（人で確かめる要あり）。ドラッグは指の約1マス上、タップは指の下に置かれ、決まりが違う |

面白さの芯：あり。予行で「倒す●●●…＞戻す●」を見て重りを替え「何も動かない」になり、本番で解けた流れ（見込み→外れ→理由→直す→当たる）が1手ずつ読める。解けた瞬間の驚きは小さめ（確定前に「この手で解ける」と出るので答え合わせになる）。

困ったところ（重い順）：
1. 本番で道具だけが落ちると「外れた」が出ず、出口はメニューの中の引き返すだけ（手詰まり）
2. 試し場が本番の地形でない（段を使う案を予行できない）
3. タップとドラッグで置かれる位置の決まりが違い、置き間違いの数え方が読めない
4. 説明の帯の倒す・戻すの比べが右で切れる
5. 置き方の候補の表示が重なって読みにくい
6. 部品の働きが分からない（ばねが弾むのを一度も見られなかった）
7. 作業台をまっさらにする手段がない、記録画面の閉じるが画面外、つり合いの余裕が見えない

違う原理の解き方：この課題と部品では「重りで押さえる」型しか見つからなかった（Q3 の材料）。
スクリーンショット：scratchpad の q1_playtest/（約70枚、リポジトリには入れていない）

## プロデューサーの判定（2026-11-19）
**直して続ける**。芯は動いた。1・2・4・5・6・7 を直す（2 は、試し場に「この課題の地形の型（敵・仕掛けなし）」を選べる形で、つまみで切り替えて人のテストで比べる。柱の「本番の地形は入れない」との差は Q1 の人のテストのあと design-director と決める）。3 は置き間違いの数え方をドラッグの持ち上げに合わせて直し、置き位置そのものは人のテストで決める。直したあと、オーナーの iPhone で人に遊んでもらって時間と置き間違いを見る。
