# マチャダン スペード Muse版 — 本番ランタイム

このディレクトリが配布版の唯一のゲーム正本です。Muse はここにある
現行ファイルだけを読み、配布物に含まれない旧資料や外部の控えを実行時の
根拠にしません。

## 4.13.4 ランタイム

- 移動時はmovement-styleを指定し、M51と既存の固定ダイスを使う。街・村の目的なし散策80％、通常の目的移動20％、目的地までぶらぶら40％、急ぎ・直行は抽選なし。移動イベントは通り過ぎられる小品でEV在庫を消費しない。

- 配分画面は火・装備等を含む最終値を主表示にし、保存用の基礎値と分ける。通常finish-turnは同じ変更JSON内のresponseから本文字数と選択面だけを確認する。

- GMの物語外発言はコア§17に従い原則出さない。お仕置き・進行不能な異常通知・安全確認の3例外だけを維持し、地の文・場面内の台詞と必要な全システム表示を残す。

- セーブ正本は `MachaDun_Save_Muse_v3`。v1/v2は検証付きで冪等に移行する。
- 戦闘は観察済み情報だけを使う敵の集中攻撃、詠唱中断、地形利用、退路遮断、撤退を含む。
- 職業事件、店舗・工房の依頼、未知素材、研究・試作・商品化は `enterprise_state`と所持品予約へ保存する。
- リリスの取立てはDay 5から5日ごとで、支払い・一部支払い・不払いと更新契約を借金台帳へ記録する。
- `status-view` と `render-status-widget` は検証済みセーブの読取専用表示を生成し、MUSE上でLP/MPから詳細と所持品へ展開できる。

町・村・施設の構造は`世界/舞台構造.json`が正本、`世界/舞台資料集.md`が人間用の全体資料です。
通常の移動・施設内行動では必要な場所だけcontextへ投影し、その場所の部屋と接続を読みます。

## 読み始める場所

1. `運用/毎ターンの約束.md` — 短い共通契約と、未定義の物語を自由に補完する方針
2. `運用/正本レジストリ.yaml` — 分野ごとの正本・補助資料・廃止資料
3. `運用/ルーティング表.yaml` — 場面ごとの必須読込パック
4. `運用/ルーティング表.md` — 上記 YAML の人間向け表示
5. `ナレッジ索引.md` — 配布されている本番ファイルの一覧
6. `saves/` の現行 YAML — キャンペーン状態の正本

Muse は記憶だけで裁定せず、場面に合うパックから一時コンテキストを生成し、
その全文を読んでからターンを処理します。正本が見つからない、または記述が
衝突した時は、`運用/正本レジストリ.yaml` の再照合手順に従います。

## 優先順位

同じ内容について複数の記述が見つかった場合は、次の順で判断します。

1. 成人のみを対象とするハードルールとユーザーが最後に確定した決定
2. 現行セーブに記録されたキャンペーン状態
3. `正本レジストリ.yaml` で `canonical` に指定された資料
4. `supporting` の補足資料
5. `superseded` は検索で見つかっても採用しない

正本が明確なら古い補足の反映漏れを修復できます。正本同士が衝突している
場合は、ダイスとセーブを進めず利用者へ確認します。

## 配布版に含めないもの

- 制作時の原資料・控え
- 旧ルートの索引や旧再構築スクリプト
- 実プレイのセーブ、バックアップ、ロック、一時コンテキスト
- `__pycache__`、テストキャッシュ、監査途中の生成物

配布ZIPは検証済みの本番ランタイム、スキル、セットアップ手順だけで
自己完結します。

通常の変更はapply-changesで完全候補へ適用し、表示用の状態抜粋からセーブを再構築しません。新事実はworld_state.campaign_loreに保存します。新しい作業用ファイルはstate/runtimeへ置き、旧版の作業フォルダは再試行用に元の場所へ残します。

文体ルールの共通部分は散策・会話・戦闘・依頼を含む全場面で毎回読み込みます。場面固有の追加ルールは必要な場面で合わせて読みます。

専用の文体を使う場面では、文体カード・専用ルール・辞書を全文読みます。保存された場面状態に従い、続きでも毎回読み、通常の場面に戻る時に解除します。選択済みの文体モードは維持します。

登録スキルはゲーム進行用machadan_gmと検査・修復用machadan_doctorの2つです。文体・戦闘・魔法・初回質問・チェキュンはGMが必要に応じて読む資料や道具です。各スキルからスキル本文・必読資料へ進む7経路を検査します。

## 4.2の通常進行

- begin-turnは現在のセーブと使用資料を検証し、場面・段階に必要な資料を集めます。文体共通部分は毎回読み、専用文体の全文読込も保持します。
- finish-turnは変更反映・保存検証・確定とステータス作成をまとめます。元の完全セーブ、保存競合・二重適用防止を維持します。
- 全17場面と在庫・保存・軽量検査の総点検は導入・更新・異常時に行います。
- 在庫は空から開始し、確定した好み・職業・現在地に合わせて少量補充します。更新時には在庫だけを新世代へ作り直し、登場済みの世界はセーブに保持します。
