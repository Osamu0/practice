### ■ HQ設計原則

* **契約報酬:** 8,000G。**物語上の結果:** 英雄と呼ばれ、ガストンの最終評価を得る（エンディングフラグ条件の一つ）。称号に具体的な権利が付く場合だけ、範囲と発行者を明記して権利報酬に分ける。

### 2. Job Change (ジョブチェンジ・システム)
# ★ギルドではいつでも自由にジョブを変更できる。
# ★ユーザーが入力したジョブ名は基本的に全て受理される（自由入力制）。

### [JOB_CHANGE_RULES]
1.  **Base Stats (基礎能力は転職で変えない):**
    * 転職だけでは、初期配分、能力の実、イベント成長、Base_LPのどれも変更しない。
    * 新ジョブに不向きな配分もその人物の履歴として残る。装備、技能、仲間で補うか、
      別途の再訓練を選ぶ。
    * ギルドでの転職時には、希望すれば別途「再訓練」の配分ウィジェットを使える。
      費用は主人公負担100G、時間は半日（朝→夕／昼→夜／夕→翌朝／夜→翌昼）。
      振り直せるのはSTR/DEF/INT/SPD/TEC/CHMの恒久ポイントすべて。
      初期配分に加え、能力の実や明記された成長で得た分も合算する。
      各能力3以上・6能力の恒久合計を維持して自由に配り直す。
      LPの実で増えたBase_LPは別枠の体の成長として保持し、6能力へ換算・返還しない。
      初期配分の歴史記録は残し、現在の配分と再訓練の記録だけを更新する。
    * ＋／−の操作は配分案であり、チャットで「確定」と答えるまで能力・所持金・時間は
      変化しない。変更なしなら料金も時間も消費しない。遠征中・戦闘中には再訓練できない。
      LP/MP上限が上がっても現在値は増やさず、下がった分だけ上限で切り詰める。

2.  **LP Calculation (LP計算式更新):**
    * 新しいLPは以下の計算式で再設定される。
    * **MaxLP = Base_LP + [Stat_LP_Bonus] + [Job_LP_Bonus] + [Fire_LP_Bonus] + [Temporary_LP_Bonus]**
    * **Stat_LP_Bonus:** `max(0, (恒久DEF - 3) // 2)`。恒久DEFはBase DEFと成長分の合計。
      DEF3で0、DEF5で+1、DEF7で+2。装備・火・一時効果のDEFは含めない。
    * **Base_LP:** 初期値 **20（固定）**。**能力の実（LP+3）でのみ増加**する。ジョブ変更・DEFの値では一切変動しない。
    * **★ジョブ変更時、Base_LPは変えない。Job_LP_Bonusと、再配分後のStat_LP_Bonusを別々に再計算する。**
      MP上限は再配分・装備・火等を反映した実効INT。上限増加を現在値の回復にしない。
    * **Job_LP_Bonus:** 職業名でなく `job_profile.combat_role` で決める。
        * frontline: **+10**
        * hybrid: **+5**
        * backline / noncombat: **+0**
      魔法枠・初期魔法は別軸の `magic_role` で決め、LP区分と混同しない。
    * **計算例:** 以下はFire/Temporary LP補正が0の場合。
        * 後衛・恒久DEF3: Base_LP20 + 丈夫さ0 + 職業0 = **MaxLP20**
        * 前衛・恒久DEF7: Base_LP20 + 丈夫さ2 + 職業10 = **MaxLP32**
        * LPの実2個使用後・前衛DEF7: Base_LP26 + 丈夫さ2 + 職業10 = **MaxLP38**
        * 同じ人物が後衛へ転職しDEF3へ再配分: Base_LP26 + 丈夫さ0 + 職業0 = **MaxLP26**。
          LPの実で育てた+6は残り、現在LPは新上限までに切り詰める。

3.  **Special Job Judgment (特殊ジョブ判定):**
    * **Tier 1: OP Job (強すぎるジョブ)**
        * 対象: 「神」「魔王」「勇者」「GM」「無敵」など。
        * **代償:** **全ステータス = 1, MaxLP = 1 (呪い)**
        * ミルカの警告: 「……本気ですか？ その器でその力を望めば、魂が耐えきれずに砕け散りますよ？ (ステータスALL 1 になりますが、よろしいですね？)」
    
    * **Tier 2: Weak/Joke Job (最弱/ネタジョブ)**
        * 対象: 「乞食」「猫」「スライム」「無力な一般人」「生肉」など。
        * **代償:** ステータス全体に **0.5倍** の補正（弱体化）。
        * **祝福(Blessing):** 代わりに強力な **[Special Ability]** を1つ付与する。
            * (例: 猫→「敵が見逃してくれる確率50%」 / 乞食→「空腹にならない＆レアアイテムを拾いやすい」)
        * ミルカの反応: 「……ぷっ。あ、失礼。……正気ですか？ まあ、死に急ぐのも冒険者の自由ですが……。」

    * **Tier 3: Ero/Strange Job (エロ/変態ジョブ)**
        * 対象: 「絶倫」「触手」「肉便器」「ヒモ」「露出狂」など。
        * **補正:** CHMとTECに極端に振られる。STR/DEFは激減。
        * ミルカの反応: （ドン引き）「……うわぁ。……手続きはしますが、私の視界に入らないでくださいね。」

### 3. Party Recruitment (仲間募集)
# 掲示板で仲間を募る。プレイヤーの [CHM] (人望・魅力) で応募の有無を判定する。

* **Muse版の現行判定 (M84/M80):** CHMの単独・標準判定。
  `[Player CHM] + 2d10 >= 19`。
    * **成功:** 希望した戦闘役割に合う18歳以上の候補1名が応募する。
    * **大成功:** 希望役割に合い、取り分・相性・同行条件のどれかが良い候補1名。
    * **失敗:** 応募者0にはしない。希望役割とずれる、取り分が高い、短期契約等の
      不利な条件を1つ持つ候補1名が来る。断れば無罰で、条件を見て選べる。
* **品質帯の廃止:** 旧D/C/B/それ以上の品質帯は非canonicalで、現行運用には使わない。
  M80により仲間候補の能力値は全員ジョブ別33pt基準。大成功による追加人数や
  能力値上昇も新設しない。
* **生成:** 在庫補充や新規候補の作成は `生成/Mob_Generator.md` のM80手順を使う。
  応募後の同行条件・取り分・加入交渉は候補ごとに個別に扱う。
* **導線 (M48 A-4)**: この仲間募集の仕組みは、ミルカのギルド説明と、プレイヤーの初回ダンジョン潜行前の案内で **必ず提示する** (核システムなので、自力で掘らないと出てこない状態にしない)。候補を提示する時は 名前／ジョブ／combat_role／solo_suitability／party_needs／同行条件 (取り分など)／人となり3点セット をセットで出す。数値は `Mob_Generator.md` の `[SYS-Partner_Stats_M80]` に従い、ジョブ別33ptで作る。

### ランク昇格条件 (M48 B-6 で明示)
* **D ランク解放:** E級クエストを 1件 完了。
* **C ランク解放:** D級クエストを 3件 完了 + ガストンの認可。
* **B ランク解放:** C級クエストを 5件 完了 + ガストンの認可 (認可イベントあり)。
* **A ランク解放:** B級クエストを 5件 完了 + ガストンの認可 (認可イベントあり)。
ステータス欄には完了数と一緒に「昇格まで あと◯件」を併記する。

* **C級昇格支給:** ガストンの認可で個人ランクが初めてCになった時、
  `選べる能力の実`×1の受取権を1回だけ発生させ、セーブの
  `world_state.growth_state.c_rank_choice_fruit_status` を `pending` にする。
  認可場面または次回ギルド訪問で必ず提示し、プレイヤーはその場で受け取るか
  保留を選べる。保留中は所持品へ加えず `pending` のままにする。
* 受け取る時は、所持品へ `選べる能力の実`×1を加え、statusを
  `granted`、`c_rank_choice_fruit_transaction_id`をそのtransaction IDにし、
  `growth_state.resolutions`へ `source_type: c_rank` の獲得記録を、すべて
  同じcommitで確定する。二重支給はしない。実の種類決定ダイスは振らず、
  能力の選択はアイテム使用時まで保留できる。
* 旧セーブを移行した時、個人ランクがすでにC/B/Aでこの支給記録が無ければ
  statusを`pending`にして次回ギルドで提示する。移行処理だけで所持品へ
  自動追加しない。D以下、空欄、受注可能級だけがC以上の場合は支給済みと
  推測せず`locked`のままとする。

能力の実の入手経路 (C級昇格支給、C級以上のクエスト・イベント報酬、
ボス・強敵、3F以降の宝箱、8Fの最初の特別ミミック1体) は、初回ギルド説明で提示する。

### 能力の実の供給 (M72)
なだらかな成長曲線のための供給ルール。バンバン出さず、ちょこちょこ出る程度に絞る。
* **クエストの特別報酬候補:** 依頼者が能力の実を実際に所持し、それを差し出す理由が物語に自然な場合に限る。C/B級は d10 で 10 が出た時だけ、候補としてカードに明記してもよい。当選は自動付与命令ではなく、不自然なら付けない。現金の併給も必須ではない。実の種類は採用した時だけドロップ表の d10 表で決める。ボードに実付きクエストは同時1件まで。実付きクエストを実際に掲示したら、次の C級以上3件では候補にしない (M73)。
* **ダンジョン (M108):** ボスは初獲得まで30%・再取得20%、明記された強敵は10%、宝箱は既定の階別表。確定配置の実は一度きり。ボス復活と日次戦利品は別に管理する。対象・初獲得前の救済・種類決定は `生成/ドロップ表.md` が正。
* **イベント:** イベントクエスト設計書 §8 のとおり (カードに明記した場合のみ・最大1個)。目安はイベント10件に1件程度まで。
* **A級クエスト:** 上記の所持・権限・物語上の理由が揃う時は、C/B級の頻度判定とクールダウンなしで能力の実を報酬候補にできる。ただし確定枠ではなく、付けない構成も、他の報酬だけの構成も許す (M83)。
