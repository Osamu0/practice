# ステータス整合性チェック（M81〜M102対応）

毎ターン、表示とセーブを確定する前に実行する。比較対象は
「直前の確定済みセーブ」と「今回のターン差分から作った次状態候補」。
`GM_BRAIN` は使わず、変化の根拠は内部のターン差分として保持する。

## 1. 確定の原則

- 直前セーブは読み取り専用の基点として扱う。
- まず次状態候補を別に作り、全チェック通過後にだけ確定する。
- 根拠のない変化を「それらしい値」へ補正して確定しない。
- 検証失敗した候補で確定済みセーブを上書きしない。
- ダイスを使った後に再構築する場合も、同じ消費済み出目を使う。
  引き直し・カーソルの巻き戻し・飛ばしは禁止。

## 2. ターン差分に必要な根拠

状態を変える処理は、少なくとも次を内部で対応づける。

- 対象キャラクターまたは世界項目
- 変更前の値
- 変更後の値
- 原因（行動、判定、購入、使用、報酬、時間経過など）
- 参照した正本と規則
- 使用したダイス種別・出目・カーソル範囲（判定がある場合）

これは内部検証用であり、思考ログとしてユーザーへ出力しない。
ユーザーへは規定の判定提示と最終ステータスだけを見せる。

## 3. 強制チェック

### A. 年齢と場面

- 恋愛・性的な関わりやエロ場面の参加者が全員18歳以上か。
- 18歳未満の人物が対象にも背景人物にも入っていないか。
- ラビラビ村の子育て・子守場面が非性的に完結し、大人同士の場面と
  明確に分かれているか。
- サキュバス女学園の在籍者が全員18〜19歳の「見習い」で、
  初等部・中等部などが生成されていないか。

違反する候補は確定せず、年齢設定または場面構成を正本どおり再構築する。
年齢が解決できない場合は性的な進行を止め、ユーザーへ確認する。

### B. Base値・LP・MP

- 主人公と同行者が同じv3 Character契約を使い、`character_id` が一意で、
  `character_version`、`build_complete`、`job_profile`、能力内訳、LP/MP、装備、
  状態を欠落させていないか。v2の主人公だけ実効値、仲間だけbase/equipという
  異なる構造へ戻していないか。
- 各能力の `effective_stats` が `base_stats + growth_bonus + equipment_bonus +
  fire_bonus + temporary_modifiers` の再計算値と一致し、旧互換の `stats` mirrorも
  同じ値か。保存済み実効値を計算根拠として逆利用していないか。
- Base値の永続変化が、能力の実・初期ボーナス・明記された
  永続効果・明記されたイベント報酬・確定済みの有料再訓練のいずれかに対応するか。
  再訓練は恒久合計を増やす成長として扱っていないか。
- LPの実は Base_LP +3。通常能力の実は対応能力 +1。
  LPの実の増加分を再訓練で失わせたり、6能力の点数へ変換・返還したりしていないか。
- `stat_lp_bonus = max(0, (base_stats.def + growth_bonus.def - 3) // 2)` か。
  装備・火・一時DEFをこの導出値へ入れていないか。
- MaxLP = `base_lp + job_lp_bonus + fire_lp_bonus + temporary_lp_bonus + stat_lp_bonus` か。
  ジョブLPボーナスは `job_profile.combat_role` の正本値から計算したか。
- MP上限は再計算後の実効INTに一致するか。
- current LP/MP が0未満または最大値超過になっていないか。
- LP0を通常攻撃の対象にせず、それ以上通常ダメージを与えていないか。
  とどめ・捕縛・救助・蘇生は、明記された個別の行動・アイテム・
  スキル・場面ルールに基づいているか。
- 転職だけでBase値やBase_LPが変わっていないか。
- 別途再訓練した時は、初期配分と実・明記された成長を含む6能力の恒久値が
  各3以上・変更前と同じ合計か。100G、半日、変更前後の配分台帳を同じ保存で照合し、
  出生記録・実の使用履歴・Base LP・所持品を保持したか。装備・火・一時補正を配分していないか。
  実使用・再訓練後の現在LP/MPが `min(旧現在値, 新上限)` となり、
  上限増加による回復・LP0からの復帰がないか。初期作成時だけは計算後の上限まで満たす。
  能力の実の使用では、未予約の持ち歩き在庫の実消費と対象人物の成長が対応するか。
  ウィジェット操作だけで確定せず、実際のstateを回収してチャットの「確定」を検証したか。

### C. 装備と計算用能力

- `weapon_instance_id / armor_instance_id / offhand_instance_id` が実在する
  `item_instances.instance_id` を指し、同じ個体を二人・二枠へ重複装備していないか。
- 動的装備の定義が `item_definitions` に完全保存され、名前だけの未知装備を
  補正計算へ使っていないか。
- 補正値と重量が `世界/Item_Database.md` の定義に一致するか。
- 外した装備の補正が残っていないか。
- 重量ペナルティが `max(0, 装備重量合計 - STR合計)` と一致するか。
- 本文の武器・防具描写が装備欄と一致するか。

- エロステ全解除は300G定額。古い「1種1000G」を使っていないか。

  落としていないか。`expedition_state.fire_holders` の名前がplayer/partyに
  必ず解決し、一時分断者もpartyに残っているか。
- 全滅発生commitはactive遠征・全員LP0・`rebirth_pending=true` を先に保存したか。

- 死に戻り精算commitの差分は、現行の危険帯に対応する正本所定の借金加算と

- 報酬受領では `settlement_id/component_id` が未受領か。同じ成分を

- 受領・辞退・失権の確定成分が `world_state.reward_ledger` に
  transaction IDつきで一意に追記され、既存の台帳成分を消去・書換え

- クエストカードを消す同じ候補で、契約の全成分が台帳または

### E. Buff・Debuff・状態異常

- 新規状態に発動根拠があり、解除に治療・時間・条件達成の根拠があるか。

  完全な不意打ち（攻撃側TEC+5 vs 守備側TEC）を使ったか。
- 防御中・回避専念中に実際の1行動の宣言根拠があり、宣言直後から
  次の自手番開始直前までの期間か。両方を同時保持せず、後の宣言へ
  切り替え、同名効果や奇襲前の未宣言効果を重ねていないか。拘束・
  麻痺・睡眠・行動不能になった瞬間、両効果を終了したか。
- 回避専念+4を SPD 攻撃対抗以外に使わず、ダメージを軽減していないか。
  状況補正を含む他の判定補正との正の合計を+5以下にし、
  能力値バフは別に扱ったか。精神・エロ・拘束対抗、状態付与率、罠・環境・
  継続・固定ダメージに適用せず、拘束・麻痺・睡眠・行動不能中に
  宣言させていないか。差1〜2のかすりは残したか。
- 持続ターンを減らし、期限切れを残していないか。
- 毒などの継続処理を正しいタイミングと値で反映したか。
- 戦闘終了・ダンジョン脱出で消える効果を持ち越していないか。

## 4. 不整合時の処理

1. 次状態候補を破棄し、直前の確定済みセーブを維持する。
2. 原因を「読み落とし／計算／差分組立／表示組立／正本衝突／
   セーブ欠損」に分類する。
3. 読み落とし・計算・組立なら必要資料を読み直し、同じ入力と
   同じ消費済みダイスから候補を再構築する。
4. 再検証に通れば通常どおり出力し、検証の内部経緯は表示しない。
5. 正本衝突・セーブ欠損・ファイル破損で一意に復旧できない時は、
   ダイス消費とセーブ更新を止める。確定済みの状態、衝突箇所、
   必要なユーザー判断を短く提示する。

「静かに直す」は、根拠のある再計算・表示修復だけに適用する。
未知の値を捏造したり、確定済みの履歴を都合よく改変したりする意味ではない。
