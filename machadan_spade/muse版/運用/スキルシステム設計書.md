# マチャダン スキルシステム設計書 (M76/M96 現行正本、2026-11-04)

M49/M50 の旧方式を経て、M76 で「習得は自由・セットに上限」の
アステリア式へ改訂した。M49/M50 の固定上限は使わない。
正本は本書。要約は数値正本 §9。

## 1. 考え方
このゲームの本体は自由入力である。宣言すれば大抵のことは
試せて、成否はその場の判断・知恵・状況とダイスで決まる
(明らかに不可能なことにはリリスのお仕置きがある)。
だからスキルは「必殺技のリスト」にはしない。スキルは
ジョブの色を固定する小さな仕組みとしてだけ置く。

## 2. 構成
- スキルは3分類され、同時に使える数 (セット上限) が決まって
  いる (M76、アステリア式)。**技 (宣言して使う手): 4** /
  **パッシブ (常駐・自動): 3** / **技能 (心得系の判定補助): 4**。
  分類の判定: 名前に「心得」と付くものは技能、宣言して使う
  ものは技、残りはパッシブ。
- スキル定義は分類とは別に `timing` と `action_cost` を必ず持つ。
  `timing` は次のいずれかとし、記載のない技は使用できない。
  - `action`: 自分の通常行動として使う。`action_cost: 1`。
  - `attack_replace`: 通常攻撃1回を置き換える。`action_cost: 1`。
  - `reaction`: 条件を満たした瞬間に割り込む。`action_cost: 0`。
    同名は1ラウンド1回まで。定義された使用回数は別に消費する。
  - `free`: 自分の手番中に通常行動を使わず宣言する。
    `action_cost: 0`、同名は1ターン1回までで、同じターンに
    能動的な技を2つ使うことはできない。
  - `battle_start`: 行動順決定後、最初の通常手番より前に1回処理する。
    `action_cost: 0`。
  パッシブは原則 `timing: always`、技能は `timing: check` とする。
  条件成立時に任意で発動する迎撃型パッシブだけは、定義に明記して
  `timing: reaction` としてよい。この場合も `action_cost: 0` と
  1ラウンド上限を必須とする。
- ジョブを決めた時点で、そのジョブのパック4つ (§6) が
  習得済み+セット済みで付く。以後も §5 の方法で追加で
  習得できる (増えない制約は M76 で廃止)。
- **習得したスキルは消えない**。セットから外したものは
  「控え」として残り、ギルドで **再セット 100G** (安全な
  非戦闘時、訓練時間なし)。満枠なら一対一で控えと交換する。
- 能動的な技は **自分の1ターンに1つまで**。必ず使用回数を持つ
  (1戦闘◯回)。`reaction` は自分の手番外に使えるが、各定義の
  1ラウンド制限に従う。回数は戦闘終了で回復。
- ジョブが変われば (転職)、`from: job` の初期パックだけが
  `origin_job` 不一致として眠る (消えない)。新ジョブの初期パックは
  同じ `skill_id` の記録を再利用し、転職の往復で重複取得しない。
  料金を払って習得した `from: standard/custom` は、個別の
  `requirements` を満たす限り転職後も使える。OP職の呪いの間は
  セット中の全スキルが封印
  される。
  呪いで全ステータスが 1 になると、帰結として INT 合計も
  1 になり、MP上限が 1・階位の門にも届かないため、魔法も
  実質的には使えなくなる (M55 で明記)。
- 魔法は別系統 (M39/M76) のまま。初期魔法と魔法枠は
  `combat_role` ではなく `magic_role` だけで決める。`caster` と
  `specialist` は初期魔法を2つ持って始める (僧侶は「癒し」+選択1、魔法使いは
  「魔弾」+選択1。スキルの枠とは別。詳細は魔法システム
  設計書 §5)。

### 2a. ジョブプロフィール (M96)
職業名は自由記述のまま、次の機械判定用プロフィールを登録時に固定する。
職業名からプレイ中に推測し直してはならない。

```yaml
job_profile:
  combat_role: frontline | hybrid | backline | noncombat
  magic_role: noncaster | hybrid | caster | specialist
  expertise_tags: []
  solo_suitability: good | difficult | unsuitable
  party_needs: []
```

- `combat_role` はLPボーナス、戦闘上の主な立ち位置、クエストの
  推奨役割に使う。魔法枠には使わない。
- `magic_role` は魔法枠と初期魔法だけに使う。能力値や職業名だけで
  自動昇格しない。変更する場合は転職・再訓練として記録する。
- `expertise_tags` は鍛冶、調合、医療、料理、服飾、鑑定、建築、
  魔道具、商売、運送等。専門設備の使用許可、専門手掛かりの自動発見、
  生産・事件判定の難易度段階に使い、単純な数値加算とは重ねない。
- `solo_suitability` はソロ禁止ではなく警告表示用。`difficult` と
  `unsuitable` は `party_needs` に必要な役割を1つ以上入れる。

標準ジョブの初期プロフィールは次を正とする。

| ジョブ | combat_role | magic_role | expertise_tags | solo | party_needs |
|---|---|---|---|---|---|
| 戦士 | frontline | noncaster | [武術, 運搬] | good | [] |
| 騎士 | frontline | noncaster | [護衛, 防具] | good | [] |
| 盗賊 | hybrid | noncaster | [開錠, 隠密, 罠] | good | [] |
| 狩人 | hybrid | noncaster | [追跡, 採集, 遠隔武器] | good | [] |
| 僧侶 | backline | caster | [医療, 薬学, 祭祀] | difficult | [frontline] |
| 魔法使い | backline | specialist | [魔法, 鑑定, 魔物学] | unsuitable | [frontline] |
| 踊り子 | backline | noncaster | [芸能, 交渉, 情報収集] | difficult | [frontline] |
| 村人 | noncombat | noncaster | [野営, 生活, 薬草] | unsuitable | [frontline] |

ここでいう「村人」は生活技能に長けた正式な標準ジョブであり、能力半減の
罰ゲーム職ではない。「無力な一般人」等の特殊な弱体状態とは別物とする。

## 3. 強さの天井
- スキルには **位階** があり、位階ごとに段1での強さの天井が
  違う (M76)。基本: **判定 ±3 / ダメージ ±3**。上級:
  **判定 ±4 / ダメージ ±5** (副次効果1つまで)。奥義:
  **判定 ±5 / ダメージ ±7** (副次効果2つまで。強い代わりに
  使用回数の少なさや代償が付くのが普通)。
- 段による強化後の上限は、位階の天井から **判定 +1 /
  ダメージ +1** まで。
- 状況補正・技能系の補正との合算上限は ±5 (数値正本 §9)。
  位階の補正もこの合算に含める。
- ダメージ補正は、技の分とパッシブの特効分を合算してよい
  (例: 天覇断 +7 と竜殺しの構え +5 は同じ攻撃に乗る)。
  判定補正の合算上限 ±5 とは別に扱う (M78)。

## 4. 強化 (成長はこれだけ)
- スキルはお金で強化する。各スキルは最大 **段3**。
- 価格: 段2 = **800G** / 段3 = **2,500G**。場所はギルド・
  訓練所・師匠。時間は半日。
- 強化の内容は各スキルの定義に「強化」として先に書いて
  ある (その場で発明しない)。
- 強化の段階はスキルごとにセーブへ記録する。転職で離れた
  スキルの段も記録は残り、戻ればその段から使える。
- ランク昇格やボス撃破でスキルは増えない・育たない。
  成長の見える化はランクと能力の実が担う (M48 B-6)。

## 5. プレイヤーの要望への対応
- **提案フロー (M76)**: 提示の引き出しとして
  運用/スキル・魔法サンプル集.md (全42件+特殊ジョブ2件、
  監査済み) を使う。プレイヤーが「こんなスキルが
  欲しい」と言ったら、GM は完全定義 (効果・数値・回数・
  制約・強化ライン) を作って提示し、「このスキルでいい
  ですか?」と確認を取る。初回の提示は §3 の位階の天井に
  収めた安全な水準にする。言われない限り GM から新しい
  スキルを提案はしない (ジョブ決定時と、§6 の初期分だけ)。
- **調整の要求**: プレイヤーが「もっとこうして」と言ったら
  意向の方向へ寄せて再提示する。天井を超える強さにする
  場合は、代償を付けて定義し直す (代償の例: 使用回数の
  削減 / LP や MP のコスト / 反動 / 発動条件 / 命中への
  ペナルティ / 使用後の疲労 / リリスの対価として借金加算)。
  強くした分に合わせて敵や世界の作りを後から調整する
  ことはしない (本人の選択として確定する)。
- **取得の価格 (M76)**:
  - 標準スキルの追加習得 (基本位階): **300G + 訓練半日**。
    他ジョブの標準スキルも、分類と個別 `requirements` が合えば学べる。
  - 上級スキル: **1,000G + 訓練半日**。奥義スキル:
    **2,000G + 訓練1日**。
  - 自作スキル (プレイヤー提案の定義): 位階に応じた価格
    (基本 500G / 上級 1,000G / 奥義 2,000G) + 訓練半日
    (奥義は1日)。ジョブ決定の場では、パックの枠を自作に
    差し替えるのは無料。
  - セットと控えの入れ替え (再セット): 100G、時間なし。
- 取得したスキルはセット上限の範囲でセットする。満枠なら
  プレイヤーが控えへ移すものを選ぶ (自動では外さない)。
- 特殊な武器や戦法の腕前 (銃・鞭・鎖鎌・二刀流など) も、
  この要望の形で受け付ける。銃そのものの扱いは M40 の
  まま (スキルなしでも撃てる)。

## 6. 標準ジョブの4つ (初期分、M96)
自由ジョブ・特殊ジョブの場合は、登録時にその概念から
同じ形の4つを完全定義して提示する (Quest_Guild の自由
ジョブ定義)。特殊ジョブの4つは「実利」が必須で、各スキル
がどの場面の何に効くかを定義に明記する (M76)。
パックは初期セットであり、§5 で追加・差し替えができる。
**初期4枠は全て基本位階に限定**し、上級・奥義を無料で入れない。
生産・専門職は原則として「危機対応または戦闘×1／現場技能×1／
生産技能×1／店舗・鑑定・調達×1」で組み、同じ効果を別名で重ねない。
登録時に `combat_role / magic_role / expertise_tags / solo_suitability /
party_needs` も同時に提示し、本人の確認後に固定する。

### 戦士
- A 強撃 (`attack_replace`, action_cost 1): 命中-2、ダメージ+3。1戦闘2回。ただし対象が
  無力状態 (拘束・睡眠・完全な不意打ち) の時は、命中
  ペナルティが消える (M69 B-2)。
  強化: 段2 回数3回 + ペナルティが消える無力状態に
  怯み・転倒が加わる / 段3 ダメージ+4。
- A 薙ぎ払い (`attack_replace`, action_cost 1): 隣接する敵2体に通常攻撃 (各ダメージ-2)。
  1戦闘2回。強化: 段2 ダメージ-1 / 段3 対象3体まで。
- P 頑健: 自分への状態付与の閾値を -1 する (M35 の SPD
  補正とは別に働く)。強化: 段2 毒の継続ダメージ -1 /
  段3 閾値 -2。
- P 踏ん張り: 戦闘不能になるダメージを受けた時、LP1 で
  耐える。1戦闘1回。強化: 段2 耐えた時に LP+3 回復 /
  段3 1戦闘2回。

### 騎士
- A かばう (`reaction`, action_cost 0): 隣にいる味方1人への攻撃を代わりに受ける (その被ダメ
  -2)。1ラウンド1回。強化: 段2 被ダメ-3 / 段3 かばう時の
  自分の対抗判定 +2。
- A 受け流し (`reaction`, action_cost 0、1ラウンド1回): 受けるダメージを半分にする。1戦闘2回。
  踏ん張りと同じ被弾には併用できない。
  強化: 段2 回数3回 / 段3 被ダメを 1/3 にする。
- P 盾熟練: 盾装備時、重量ペナルティを 2 軽減。
  強化: 段2 3軽減 / 段3 盾を持つ手の攻撃の命中 +1。
- P 頑健: 戦士と同じ。

### 盗賊
- A 急所狙い (`attack_replace`, action_cost 1): この攻撃は痛恨条件が 2d10 合計 17以上 に
  なる。1戦闘2回。強化: 段2 条件16以上 / 段3 回数3回。
- A ステップ (`action`, action_cost 1): 反撃を受けずに離脱・移動する。1戦闘2回。
  強化: 段2 回数3回 / 段3 離脱後の次の命中 +2。
- C 開錠の心得: 開錠の判定 +3。強化: 段2 罠の解除にも
  +2 / 段3 開錠 +4。
- C 隠密の心得: 隠れる・忍び込む判定 +2。
  強化: 段2 +3 / 段3 仲間1人も一緒に隠せる。

### 狩人
- A 急所狙い: 盗賊と同じ。
- A 足払い (`attack_replace`, action_cost 1): 命中した敵は、次の自分の行動まで全ての判定
  -3。1戦闘2回。強化: 段2 回数3回 / 段3 SPD も -2。
- C 追跡の心得: 追跡の判定 +3。強化: 段2 罠の発見 +2 /
  段3 追跡 +4。
- P 弾薬管理: 戦闘後、安全な場所で使った矢・弾の半分を
  回収できる。強化: 段2 全部回収 / 段3 全部回収し、獣を
  倒した時の素材ドロップ判定をもう1回振れる。

### 僧侶 (魔法「癒し」習得済みで開始)
- A 応急手当 (`action`, action_cost 1): 味方1人の LP を 1d6+2 回復する。対象ごとに
  1回まで、1戦闘2回。強化: 段2 回復 1d6+4 / 段3 状態
  異常も1つ治す。
- A 鼓舞 (`action`, action_cost 1): 味方1人の次の判定 +2。1戦闘2回。
  強化: 段2 +3 / 段3 味方全員に +1 (回数は同じ)。
- C 薬草の心得: 薬草の採取・調合の判定 +2。
  強化: 段2 +3 / 段3 採取の量が2倍。
- P 頑健: 戦士と同じ。

### 魔法使い (魔法「魔弾」習得済みで開始)
- A 集中 (`free`, action_cost 0): 自分の手番で魔法を使う直前に宣言し、
  その魔法の命中 +2。集中だけを宣言して後のターンへ保持できない。1戦闘2回。
  強化: 段2 その魔法の威力も +1 / 段3 回数3回。
- A ステップ: 盗賊と同じ。
- C 魔物の心得: 魔物の弱点・行動の知識判定 +2。
  強化: 段2 +3 / 段3 戦闘開始時に弱点を1つ自動で知る。
- P 夜目: 暗闇ペナルティを 1 軽減。
  強化: 段2 2軽減 / 段3 暗闇でも罠を発見できる。

### 踊り子
- A 鼓舞: 僧侶と同じ。
- A ステップ: 盗賊と同じ。
- C 交渉の心得: 値切り・説得の判定 +2。
  強化: 段2 +3 / 段3 一般小売・宿泊・通常サービスに限り
  値切りの価格ロックが 75% になる。鍛造・研究・特殊注文・
  依頼材料は `定価80%` と `実原価` の高い方を絶対下限とする。
- P 夜目: 魔法使いと同じ。

### 村人
- A 応急手当: 僧侶と同じ。
- A 足払い: 狩人と同じ。
- C 野営の心得: 野宿の安全判定 +3。強化: 段2 食料が
  なくても MP 回復が落ちない / 段3 野宿で LP も +3 回復。
- C 薬草の心得: 僧侶と同じ。

## 7. 仲間と敵
- 仲間 NPC も、そのジョブの4つを持つ。追加習得・強化も
  プレイヤーと同じルールで、その NPC 自身の所持金で払う
  (プレイヤーが負担する場合はその場で合意を取る)。
- 敵にスキルは持たせない。ボス・強敵の個性は M35 の特殊
  能力が担う。

## 8. セーブ形式 (M76)
skills: は習得済み全件のリストにする。
  - {skill_id, name, category: technique/passive/check, tier:
    basic/advanced/master, stage: 1-3, state:
    set/reserve/dormant_by_job, uses: 回数 (技のみ),
    timing: action/attack_replace/reaction/free/battle_start/always/check,
    action_cost: 0/1, effect: 定義文, from: job/standard/custom,
    origin_job: 全件でキー必須。from=jobは元職名、standard/customはnull可, requirements: []}
job_profile は §2a の5項目を保存する。プロフィールは職業名から再生成しない。
自作スキル・自作魔法の完全定義は custom_abilities に
保存し、名前から再生成しない。

## 9. 既存セーブの移行
スキル導入前に始まったセーブは、次回のギルド訪問時に
現在のジョブの4つ (段1) が付く。
M76 への移行: 既存の所持スキルは全て「習得済み+セット中」
として引き継ぐ (段も保持)。次回のギルド訪問時にミルカが
一度だけ、新しい習得方式 (追加習得・位階・控え) を案内
する。
既存の名前が「心得」で始まる／終わるスキルは `category: check` へ
移行し、パッシブ枠から技能枠へ移す。既存ジョブ由来の4件には
`origin_job` を付け、購入履歴が確認できるものは `from: standard/custom`
として転職後も維持する。由来が判別不能なら自動で休眠させず、次回ギルドで
本人に確認して確定する。

## 4.13.0 由来の項目

`origin_job`という項目自体は全スキルに置く。職業初期パック（`from: job`）は元の職名を文字列で保持する。購入・自作（`from: standard/custom`）で元職がない場合は`origin_job: null`とする。この項目があるだけで転職時に使えなくすることはなく、休眠は既存のfromとrequirementsで判断する。設計書を現行検証器・既存スキーマに合わせたもので、スキル効果や習得条件は変更しない。
