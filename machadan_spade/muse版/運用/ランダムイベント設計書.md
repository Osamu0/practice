# ランダムイベント設計書 (M51/M82/M83/M92 確定、2026-11-04)

街・村と道中の移動や日常行動に、小さな出来事を返す仕組み。
素材は同梱の `生成/Overworld_Encounters.md` 等を使うが、旧移動1d6表は振らず、以下のM51で一本化する。

## 1. 発動条件

- 街・村の中の移動と、街の外への道中を対象とする。通常の目的移動にもM51を使う。
- 緊急の移動、本人が明言・選択した直行にはM51を振らない。スタイル不明の「○○へ行く」は通常の目的移動。
- 緊急とは、本人が「急ぐ」と明言した移動、期限・追跡・救助・逃走など実際の時間圧を持つクエスト中の移動、怪我人・病人を運ぶ等の移動。クエストがアクティブというだけでは緊急にしない。曖昧なら通常の20％。
- **ダンジョン内ではM51を振らない**。`世界/Dungeon_Data.md` §1とEV-D在庫等の専用規則を維持し、M51の確率・街や道中の種別表・100G相当までの上限を混用しない。専用イベントとC-7を同じ場面へ重ねない。
- 「店を開ける」「工房で仕事を待つ」「製作依頼を探す」は仕事開始であり、M51を追加しない。M92の1日1回・短い3候補・進行中注文の規則を維持する。
- 帰還の腕輪による瞬間帰還は徒歩の道中ではない。街路の移動イベントを挟んで帰還を妨げない。

## 2. 判定

| 行動 | M51の発生判定 |
|---|---|
| 緊急の移動 | 振らない |
| まっすぐ向かう（本人が明言・選択） | 振らない |
| 通常の目的移動（スタイル指定なし） | d10で2以下（20％） |
| 目的地までぶらぶら歩く・寄り道しながら向かう | d10で4以下（40％） |
| **街・村を目的なくぶらつく・散策する** | **d10で8以下（80％）** |
| 道中の目的のない散策、休憩・暇つぶし等の従来の日常行動 | d10で4以下（40％） |

- 目的のない街・村の散策80％は、2026-11-06の追加依頼「高確率」を優先した変更。宝や報酬を必ず得る意味ではない。
- 対象の移動・日常行動1回につき発生d10を1件だけ消費し、当たった時だけ直後のd10で§3の既存の種別表を引く。外れでは種別を振らない。通りや扉ごとに抽選を増やさない。
- `random_event_roll`へdie=d10・result・cursorを記録し、当選時は`random_event_type_roll`も同じ形で記録する。現行の固定テープとcursorを使い、同じ移動への応答・見送り・続きで引き直さない。
- 表示はそれぞれ `d10 = <出目>` だけ。発生の有無、種別名、閾値、確率や内部キーは読み上げない。
- M51が出た場面ではC-7を出さない（大きな出来事は1場面1つ）。外れではC-7を通常の該当条件で扱う。急ぎ・直行の途中にC-7を口実に足止めを作らず、到着後の別場面は従来の条件に従う。
- M47の受注時のイベント判定とは別枠。M47を移動のたびに振ったり、M51をM47の代わりにしたりしない。

### 2.1 移動スタイルの選択肢

- 移動先を選ばせる場面では、原則「ギルドへまっすぐ戻る／ギルドまでぶらぶら歩いていく」のように、同じ行先の直行と寄り道を対で示す。今の行先と既知の道だけを使う。
- 緊急ならぶらぶらの候補を出さず、急いで向かう候補と今必要な別行動にする。戦闘・交渉中や、移動が主題でない場面の全候補へ機械的に対を付けない。
- 日常の街の自由行動では「目的を決めずに街をぶらつく」も自然な候補にできる。毎回同じ長い案内を付けず、普段の候補数に収める。

### 2.2 移動イベントと短い道中

- **移動イベントは通り過ぎられるものだけ。** 声をかけられる、離れた場所の出来事を目撃する、小さな頼み事や路地の風景などを提示し、関わるかは本人に委ねる。道中の魔物や罠も、進路を塞ぐ強制戦闘・強制被害に作り替えない。
- 用事・クエストの本筋を乗っ取らず、到着を阻害しない。見送ればそのまま目的地に着ける選択肢を必ず出す。関わる場合も1〜3ターンの小品とし、長編や強制受注にしない。
- **移動イベントにはEV在庫を消費しない。** §3の既存種別表、Overworldの素材、街のC-7の風景からその場で作る。既存イベントの追補本文は素材として参照できるが、在庫IDを消費・再登録して移動を賄わない。
- 移動を伴わない従来の日常行動では、適合在庫を使う従来経路を維持する。ダンジョン在庫にも変更を加えない。
- 外れ・急ぎ・直行では、場所や街路の構造に合う通りの様子・天気・同行者の様子を2〜3行だけ描いて到着する。移動だけを650字へ水増ししない。到着後に会話・出来事が始まるなら、その本編は従来の文体と字数で描く。
- ミルカとリリスの散策案内は各人格ファイルの追加サンプルを使う。実際にその場で会話する時に一度だけ短く言い、確率を講義せず、散策を強制しない。

## 3.1 エロ種別の発展方針 (2026-11-06 追補)
- 街の出目1-2 (エロい誘い) の素材として、イベントデッキ EV-S16 (異世界の衣装のサキュバス)／EV-S17 (サキュバスだと言い張る獣人) を使う。
- エロい遭遇は「風景として処理し本格化させない」で打ち切らない。プレイヤーが進めれば本気の交尾まで行くのが既定 (全体方針は 運用/イベントデッキ.md の運用ルール)。
- ダンジョン側のエロはイベントデッキの種別11 (DE-A〜DE-D) が受け皿。本書の種別表は街・道中専用で、ダンジョンへ混用しない (従来どおり)。

## 4. 規模と素材
- 長さは 1〜3 ターンで完結させる。持ち越し・伏線は
  作らない (続く物語は M47 のイベントクエストの仕事)。
- 名前付き NPC は、その場の役割がある使い捨てに限る。
- 報酬は小さく (100G 相当まで)。現金に限らず、品物・小さなサービス・
  情報等でも、無報酬でもよい。種類数をそろえず出来事と提供者の自然さを
  優先する。複数成分ならプレイヤーは全部、一部だけ、全て辞退を
  選べる。能力の実は出さない。
  戦闘は雑魚1エンカウントまで。
- 小報酬を申し出る時も、即時用の簡易 `reward_contract` を作り、
  `settlement_id` と成分ごとの `component_id/kind/state` を固定する。
  現金だけの時も省略しない。無報酬なら `offered: false`、componentsは
  空でよく、台帳成分は作らない。
- その場での受領・一部受領・辞退を、実体差分と
  `world_state.reward_ledger` の追記に同時反映する。deliveredは
  反映先の前後ハッシュ（金はamountも）をeffectへ記録し、declinedは
  `effect: null` とする。ランダムイベントのまま後日受取は作らず、
  その場で渡せない約束になったら正式クエストへ昇格させる。

簡易契約の必須形は次のとおり。

```yaml
reward_contract:
  settlement_id: "EVR-<campaign>-<turn>-<stable-id>"
  offered: true
  payer: ""
  components:
    - component_id: ""
      kind: "gold/item/right/service/favor/referral/information"
      detail: {estimated_value_g: 0}  # 金はamount、品物はitem_name/quantityも必須。他は発行者、対象、範囲、回数/期限等
      state: "offered"
  delivery_plan: [{trigger: "その場", route: "提供者から直接"}]
```

`detail` はkindに合う次のどれかを使う。合わせて一つの契約へ
全種を入れる意味ではない。

```yaml
gold_detail:
  {estimated_value_g: 50, amount: 50}
item_detail:
  {estimated_value_g: 30, item_name: "薬草束", quantity: 1}
entitlement_detail: # right、または後日使うservice/favor/referral/information
  estimated_value_g: 60
  delivery_target: "world_state.entitlements"
  entitlement_id: "EVR-...-benefit"
  name: "診療所1回利用権"
  issuer: "旅の薬師"
  scope: "街の診療所"
  conditions: []
  uses_remaining: 1          # 無制限だけnull
  expires: null              # 期限があれば文字列
immediate_detail: # その場で完了するservice/favor/referral/information
  estimated_value_g: 20
  delivery_target: "session_log"
  summary: "毒消し草の見分け方"
```

IDは初回提示時に固定し、プレイヤーが辞退した後に別IDで出し直さない。
回答・清算までは `world_state.event_reward_contract` にこの簡易契約を保持し、
受領/辞退を `reward_ledger` へ確定した同じ候補でnullへ戻す。
各componentの `estimated_value_g` 合計は100以下とし、台帳へも同値を
複写する。清算時には payer、kind、見積価値、金額、品名・数量を契約から
すり替えない。台帳の `source.kind` は `random_event`、statusはsettled /
declined / forfeitedのいずれかとし、partialやpendingにしない。

- right/service/favor/referral/information はdetailに
  `delivery_target` を持つ。後日利用する利益なら
  `world_state.entitlements` とし、`entitlement_id/name/issuer/scope/
  conditions/uses_remaining/expires` を受注時に固定する。その場で
  完了する役務・情報なら `session_log` と `summary` を固定する。
- session_log反映行は通常の描写に加え、
  `reward_delivery: {settlement_id, component_id, kind, summary}` を持たせる。
  候補作成後にreward-effectの `appended_log_entries` から行番号と
  ハッシュをeffectへ写す。
- 辞退成分と同じ金・品名・entitlement_idの無関係な増減は、
  同じ清算commitに混ぜない。辞退と実体付与を機械的に分離できなくなるためである。
- 素材: 道中側は `生成/Overworld_Encounters.md` の
  各節を素材庫として使う (イベントクエスト設計書 §11 の
  変換規則 = 成人化・数値変換・報酬の付け替え を必須)。
  街側は Locations の施設設定と World_Setting の街の
  エロ風景 (C-7) も素材にする。

### 4.1 種別9から正式クエストへの昇格

街・村の種別9で、`job_profile.expertise_tags`、現在の仕事、または
`enterprise_state` の店・工房に適性があれば、客が「作ってほしい」
「発明してほしい」「こんな悩みを解決できる物がほしい」と相談を
持ち込む展開を優先候補にする。客が完成品の名前を知っている必要はない。
物を作らず、診断・鑑定・事故調査・真贋判定等の知見で解く相談なら、
M92の `professional_case` へ昇格する。

- ランダムイベントの範囲では、依頼人の人となり、困っている実景、
  今でなければならない理由、受けるかどうかだけを1〜3ターンで描く。
- 受けた瞬間にこのランダムイベントを完了扱いで閉じ、M47 §4.1の
  `quest_card` を全欄生成して通常クエストへ昇格する。その後、仕事
  1件としてM47のイベント発生判定を **1回だけ** 行う。
- 昇格後は本節の「1〜3ターン・100G相当まで」ではなく、M47の規模・
  報酬・物語ビートを適用する。両方の上限を混在させない。
- 断れば無罰でその場で閉じる。生産職でなければ、従来型のクエスト
  の種にするか、適任職人を紹介する小イベントとして完結させる。
- 直前に正式化したクエストも生産依頼だった場合は、同型の連続を避け、
  別の種を優先する。
- この変換はイベント在庫の文面より優先する。古い在庫の種別9を引いた
  場合も、生産職なら本項どおり相談へ読み替えられる。
- この種別9は、店舗営業の1日1回の客生成とは別の「偶然の相談」である。
  店舗に紐づけて受注する場合だけ、その店の `active_order_id` を使い、同店舗で
  複数の有償注文を抱えない。店舗外の職業相談は `business_id: null` で
  `order_book` へ登録し、すでに進行中の単発仕事があるなら新規受注はできない。
  断るか紹介だけで閉じた場合は店舗の客抽選を消費しない。
