# 05 本格的な開発開始

本制作に入るための土台を作る部門。ここからのコードは捨てない。

## 仕事人と呼ぶ順

1. `game-prod-architect`（設計と土台のコード、規約）
2. 土台ができたら、`game-prod-planner`（バックログ）と `game-prod-pipeline`（ビルド・テスト・アセット）を**同時に**
3. プロデューサーが、バックログの最初の山（縦切りを本番の土台に載せ直す）を確かめる → ゲート05

## バックログの型

| ID | 名前 | 部門・担当 | 依存 | 完了条件 | マイルストーン | 状態 |
|---|---|---|---|---|---|---|
| T-001 | プレイヤーの移動 | 06 game-sys-gameplay | なし | 機能仕様「移動」の受け入れ条件 | アルファ | 未着手 |

- 状態：未着手 → 作業中 → レビュー待ち → 完了
- 1タスクは1人が1回で終えられる大きさ

## ゲート05

- 土台が起動し、自動テストが1つ以上通る
- ビルド・テスト・起動のコマンドが `README.md` にある
- データ（数値、テキスト）を外から読む形になっている
- バックログが、アルファまでのタスクでマイルストーンに割り付いている

## この部門に加わる仕事人

中心の仕事人（上の「呼ぶ順」）に加えて、プロジェクトに要るときに呼ぶ。`開発チーム.md` で使わないと決めた仕事人は呼ばない。

| 仕事人 | 職種 | この部門でやること |
|---|---|---|
| `game-tech-director` | テクニカルディレクター | 設計と土台を判定する |
| `game-tech-engine` | エンジンエンジニア、システムプログラマー、物理演算プログラマー | 土台のうち、ゲームループ・時間・シーン・入力を作る |
| `game-tech-graphics` | グラフィックスプログラマー | 描画の土台（カメラ、描画の順番、解像度の扱い） |
| `game-tech-network` | ネットワークプログラマー | 通信の土台 |
| `game-tech-backend` | サーバーエンジニア、バックエンドエンジニア、データベースエンジニア | サーバーの土台、APIの決め、データベースの設計 |
| `game-tech-tools` | ツールプログラマー | 作業の流れを聞いて、要るツールの一覧を作る |
| `game-tech-platform` | プラットフォームエンジニア | 端末ごとの入力・保存・画面の扱いの土台 |
| `game-art-technical` | テクニカルアーティスト、テクニカルアニメーター、リギングアーティスト | 資産の取り込みの手順と、チェックの道具 |
| `game-pm-manager` | プロジェクトマネージャー、プロダクションマネージャー、制作進行担当、リソースマネージャー、アシスタントディレクター | バックログの運用の決め（状態、見直しの間隔） |
| `game-pm-secretary` | 会議・情報管理担当 | 文書の目次と、仕事人向けの説明資料（`オンボーディング.md`） |
| `game-qa-automation` | 自動テストエンジニア | 自動テストの仕組みの土台 |
