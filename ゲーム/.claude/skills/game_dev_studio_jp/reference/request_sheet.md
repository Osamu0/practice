# 依頼書

この環境で作れないもの、作れても品質が足りないものを、外部の人に作ってもらうための書類。仕事人は「何を、どんな形で作ってほしいか」を書く。依頼先を選ぶこと、連絡、契約、支払い、権利の取り決めはオーナーが行う（このスキルの範囲外）。

目指すのは、**ゲームを知らない人が、依頼書だけを読んで、こちらが欲しいものを作れる**こと。読んだ人が質問しなくて済むほど、やり直しが減る。

何を外部に頼むかは、ゲームごとに違う。プロジェクトごとに、下の「外部に頼むかの判断」で決める。

## 外部に頼むかの判断

02 プリプロダクションで、`game-preprod-producer` が企画書・デザインの柱・技術選定・アートディレクションを読み、この表に照らして依頼一覧の初版を作る。プロデューサーがゲート02でオーナーに見せ、頼むものを決めてもらう。

| 種類 | 頼むことが多いとき | この環境でできること（頼まないとき） | 依頼書を書く | 依頼書と届いたものを見る |
|---|---|---|---|---|
| イラスト | キャラ・背景・キービジュアルを絵の質で見せたい | SVG、ドット絵、単純な形の絵 | `game-art-concept` | `game-art-director` |
| 3Dモデル・質感 | 3Dのゲームで、作り込んだキャラ・背景が要る | 単純な形の組み合わせ、手続き生成 | `game-art-3d` | `game-art-director` |
| アニメーション | 動きの多い手描きの2Dアニメ、作り込んだ3Dの動き | 補間で動かす、単純なコマのアニメ | `game-anim-animator` | `game-art-director` |
| BGM（音楽） | 曲の質で印象を作りたい、生の楽器の音が要る | 合成音の曲、短いジングル | `game-audio-composer` | `game-audio-director` |
| 効果音（録音） | 生っぽい音（足音、布、金属、環境の音）が要る | 合成した電子的な効果音 | `game-content-sound` | `game-audio-director` |
| 声（ボイス） | キャラがしゃべる | なし（声なしで遊べる形にする） | `game-audio-voice` | `game-audio-director` |
| 翻訳の最終確認 | 多言語で出す | 翻訳と、ビルドの上での確認 | `game-loc-director` | `game-loc-lqa` |
| 実機テスト | スマホ・ゲーム機など、ここにない端末で出す | ブラウザ、画面の大きさを変えたテスト | `game-qa-lead` | `game-qa-lead` |
| フォント | 作品らしい文字を使いたい | 自由に使えるフォントから選ぶ | `game-art-ui` | `game-art-director` |

- 「頼む」「頼まない」「あとで決める」のどれかを決める。頼まないものは、この環境でできる形で作る
- 途中で企画が変わったら、依頼一覧を見直す（頼む予定だったものが要らなくなる、新しく要るものが出る）
- 時間がかかるもの（主役の絵、BGM、声）は、早めに依頼書を書く。縦切りで使うものは 04 プロトタイプの頃から書いてよい

## 置き場所と流れ

- 置き場所：`07_コンテンツ/依頼書/<種類>/<依頼ID>_<名前>.md`（種類：イラスト、3D、アニメ、BGM、効果音、声、翻訳、実機テスト、フォント）
- まとめの一覧：`07_コンテンツ/依頼書/依頼一覧.md`
- 流れ：
  1. 書く担当が依頼書を書く。ゲームの中には、本番と同じ大きさ・長さの仮のものを先に置く
  2. 見る担当が依頼書を見る（抜け、あいまいなところ、方向とのずれ）。「必ず直す」が0になったら、プロデューサーがオーナーに渡す
  3. オーナーが「オーナーが書く欄」を埋めて依頼する
  4. 途中のもの（ラフ、デモ、試しの録音）と完成が届いたら、見る担当が依頼書の「確認の基準」に照らして見る。直しの依頼の文も書く
  5. 完成を、その種類の担当が取り込み、ゲームの中で確かめて、資産一覧（サウンド一覧）を「本番」にする
- 届くのを待たずに、仮のもののまま開発を先に進める

## 依頼書の型（全種類共通）

```markdown
# <種類>依頼書：<依頼ID> <名前>

## 1. ひとことで
<何を、ゲームのどこで使うか。1〜2文>

## 2. このゲームについて（作る人向けの短い説明）
- どんなゲームか：<一文の企画>
- 雰囲気：<アートディレクション・音の方向の言葉>
- これを見た・聞いたプレイヤーに感じてほしいこと：
- 伝えてよい範囲：<物語のネタばれをどこまで伝えるか>

## 3. 作ってほしいもの
<種類ごとの項目（下）>

## 4. 決め（変えてはいけないところ／自由にしてよいところ）
- 変えてはいけない：
- 自由にしてよい：
- 参考：<添付のファイル名>（既存の作品・曲・人の名前で「〇〇みたいに」とは書かない。技法と雰囲気の言葉で書く）

## 5. 技術の条件
<種類ごとの項目（下）>

## 6. 納品してほしいもの
| ファイル | 数 | 段階（途中／完成） |
|---|---|---|

## 7. 確認の基準（届いたものを、これで確かめる）
- [ ] <種類ごとの項目（下）>
- [ ] 技術の条件どおり
- [ ] 既存の作品・曲に似すぎていない

## 8. オーナーが書く欄（仕事人は空けておく）
- 依頼先：
- 締め切り：
- 予算：
- 権利・使える範囲・クレジットの書き方：
- 連絡の方法：

## 9. 添付
- <仮のもの、ラフ、見本、画面のスクリーンショット、ゲームの録画など>
```

## 種類ごとの項目

### イラスト

- 作ってほしいもの
  - キャラ：名前・役割、年齢の感じ・体つき・身長（ほかのキャラとの比較）、性格（3語）と見た目に出るところ、服・髪・持ち物（色コードつき）、ポーズ・向き、表情の差分（使う場面つき）、見分けるために必ず入れる特徴
  - 背景：場所・時間帯・天気、キャラや操作の表示が重なる場所（そこに大事なものを描かない）、遠景・中景・近景を分けるか
  - 小物・アイコン：それぞれの名前とゲームでの意味、小さく表示されても形で見分けられること
  - 見た目：スタイルの言葉（使う／使わない）、色コードのパレット、線、塗り、光の向き
- 技術の条件：画像の大きさ（px）と縦横比、ゲーム画面での表示の大きさ、透過、余白、形式（PNG、レイヤーつきの元データが要るか）、パーツ分け、差分の作り方、ファイル名
- 確認の基準：色が指定から大きくずれていない、必ず入れる特徴がある、表示の大きさに縮めても形と表情が読める、パーツと差分の分け方
- 同じキャラを何枚も頼むときは、最初に設定画（正面・横・色）を1枚頼み、以降の依頼書の添付にする

### 3Dモデル・質感

- 作ってほしいもの：形（正面・横の設定画を添付）、大きさ（ゲームの単位で）、動かす部分、質感（金属、布、肌など）、色コード
- 技術の条件：ポリゴン数の上限、テクスチャの大きさと枚数、骨（リグ）の要否と骨の名前の決め、原点と向き、形式（glTFなど）、ファイル名
- 確認の基準：上限の数値に収まる、ゲームに読み込んで向きと大きさが正しい、ゲームのカメラの距離で形が読める

### アニメーション

- 作ってほしいもの：動きの一覧（名前、長さ、ループか、始まりと終わりの姿勢）、動きの狙い（重さ、速さ、誇張の度合い）、操作を受け付けるタイミング（どのコマから次の動きに移れるか）
- 技術の条件：2Dならコマ数と1コマの大きさ・並べ方、3Dなら骨の名前・フレームレート・形式、ファイル名
- 確認の基準：決めた長さに収まる、操作に遅れて見えない、ループのつなぎ目が跳ねない、ほかの動きへの切り替えが自然
- 添付：仮の動きの録画、手ざわりの決め（ゲームデザインの担当と合わせたもの）

### BGM（音楽）

- 作ってほしいもの：曲の一覧（場面、感じさせたいこと、テンポ、楽器、長さ）、場面の変化での切り替え（重ねる、つなぐ、止める）、ゲームの遊びのテンポ（1回の遊びの長さ）
- 技術の条件：ループの始まりと終わり（つなぎ目で切れない、跳ねない）、形式（WAV、OGGなど）、サンプリングの周波数、音の大きさの基準、切り替え用に楽器ごとに分けた音（ステム）が要るか、ファイル名
- 確認の基準：ゲームの中でループして切れ目がわからない、効果音と声が埋もれない、場面の感じが伝わる、決めた長さ・テンポ
- 添付：ゲームの録画（音なし）、仮の曲、場面ごとのスクリーンショット

### 効果音（録音）

- 作ってほしいもの：音の一覧（名前、鳴るきっかけ、長さ、質感、何回くらい鳴るか）、同じ音のばらつき（何種類か）
- 技術の条件：形式、サンプリングの周波数、頭と終わりの無音の長さ、音の大きさの基準、ファイル名
- 確認の基準：鳴るきっかけと音がずれない、何度も聞いて疲れない、ほかの音と聞き分けられる

### 声（ボイス）

- 作ってほしいもの：キャラごとの声の方向（声の質、年齢の感じ、話す速さ、演技の幅。実在の人の名前で指定しない）、収録台本（ID、キャラ、台詞、場面、気持ち、長さの目安、読み方の注意）、言語
- 技術の条件：形式、サンプリングの周波数、頭と終わりの無音の長さ、音の大きさの基準、1台詞1ファイル、ファイル名（台本のIDと合わせる）
- 確認の基準：台本どおり（読み間違い、抜け）、気持ちが場面に合う、ノイズがない、ファイル名がIDと合う
- 添付：キャラの設定と口調サンプル、場面のスクリーンショット
- 実在の人の声をまねた合成音声は使わない

### 翻訳の最終確認

- 作ってほしいもの：言語ごとの、ネイティブの人による訳の確認と直し
- 渡すもの：テキストのデータ（IDつき）、用語集、キャラごとの口調、文脈（どの画面で、誰が、何文字まで）、言語を切り替えたビルドの遊び方
- 技術の条件：直しはテキストのデータに書く（IDを変えない）、文字数の上限
- 確認の基準：用語のゆれがない、文字数の上限を守る、画面の上ではみ出さない

### 実機テスト

- 作ってほしいもの：決めた端末での、テスト項目の実行と結果
- 渡すもの：端末の一覧（機種、OS）、ビルドの入れ方、テスト項目（`11_QA/テスト計画.md` から）、バグの報告の形（`10_ベータ/バグ表.md` の型）
- 確認の基準：全部の項目に結果がある、バグに再現手順がある

### フォント

- 依頼ではなく、選ぶもの。この依頼書は「選ぶための条件」を書く
- 作ってほしいもの：使う場所（タイトル、本文、数字、UI）、雰囲気の言葉、要る文字（ひらがな、カタカナ、漢字の範囲、英数、ほかの言語）、太さの種類
- 確認の基準：小さい大きさで読める、要る文字が全部ある、ゲームの中で使える条件（オーナーが確かめる）

## 書くときの決まり

- 数字にできるものは数字で書く（色コード、px、秒、テンポ、数、表示の大きさ）。「いい感じに」「おまかせ」は、自由にしてよいところにだけ使い、そう明記する
- 添付は必ず付ける。この環境で作れるもの（ラフ、色見本、仮の曲、ゲームのスクリーンショットや録画）を書き出して、`07_コンテンツ/依頼書/<種類>/添付/` に置く
- 既存の作品・曲・キャラ・実在の人物の名前で指定しない
