# 見た目のデザインの作り方

キャラ・敵・背景・小物・UIの見た目を、現場と同じ往復（たくさん出す → 絞る → 清書する → ゲームの画面で見る → 監修 → 直す）で決める手順。1案を描いて終わりにしない。

| 担当 | この手順でやること |
|---|---|
| `game-preprod-art` | 方向（形の言葉、比率、パレット、並べ図の決め）を決める。段階の土台 |
| `game-story-lore` | キャラの中身（役割、性格3語、望み、見た目に出るところ）を、設計書に渡せる形で書く |
| `game-art-concept` | 設計書から段階1〜6を回し、設定画を決める。本番を外に出すなら依頼書を書く |
| `game-art-ui` | UIの部品とアイコンを、同じ段階で作る |
| `game-art-director` | 段階2（絞る）と段階7（監修）で見る。届いた本番の絵も見る |
| `game-content-art` | 決定した設定画からだけ、ゲームの資産（仮か本番）を作る |

## この環境で描く絵の役目

この環境で描く絵（SVG、Canvas、ドット絵）は、**設計と仮**。キャラ・背景のように絵の質で見せたいものは、本番の絵を外で作る前提にする（外部の絵描きか、オーナーが選んだ画像生成の道具。依頼一覧で「頼まない」と決めたものは除く）。

だから、この環境の絵の基準は「描き込みのきれいさ」ではなく、次の3つ。

1. **遊びで読める**：ゲームの表示の大きさで、役割（味方か敵か、強さ）、向き、状態がわかる
2. **決めが伝わる**：形、比率、色コード、必ず入れる特徴が、外の人に誤解なく伝わる
3. **仮のままでも遊べる**：本番と同じ大きさ、同じ当たりの位置、同じ足元の位置

描き込みに時間をかけるより、**案の数**と、**ゲームの画面で確かめる回数**に時間をかける。

## 置き場所

```
07_コンテンツ/デザイン/<種類>/<名前>/
  設計書.md        … 段階0
  ラフ一覧.svg/.png … 段階1（全案を1枚に）
  絞り込み.md       … 段階2・3（残した3案と理由、色の案）
  並べ図.svg/.png   … 段階4
  設定画.svg/.png   … 段階5（決定版）
  画面確認/         … 段階6のスクリーンショット
```

種類：キャラ、敵、背景、小物、UI。02 プリプロのスタイル見本は `02_プリプロ/スタイル見本/` のままでよい。

## 段階

### 0. 設計書（デザインのお題）

描く前に、何のためのデザインかを決める。設計書のない絵は描かない。

- 遊びでの役割：味方／敵／中立、強さ、何をするか、どこに出るか
- プレイヤーに一目で伝えたいこと：3つまで（例：「足が速い」「近づくと危ない」「仲間にできる」）
- 中身（`game-story-lore` の設定から）：性格を3語、望み、見た目に出すところ
- 表示の条件：ゲーム画面での大きさ（px）、カメラの角度、後ろの背景の色、同時に並ぶもの
- 形の言葉：アートディレクションの決め（例：丸＝味方・やさしい、角＝固い、とがり＝危ない）を、このデザインでどう使うか
- 決まっている色、使ってはいけない色（ほかのキャラ・敵・危険の色とかぶらないか）
- 似せてはいけないもの：既存の作品、同じゲームのほかのキャラ

### 1. ラフ出し（シルエット）

- 数の目安：キャラ・敵は1体につき**12案以上**、背景は1場面につき構図**6案以上**、小物・アイコンは1つにつき**6案以上**
- 黒一色のシルエットか、明暗3段だけで描く。色はまだ付けない
- **ゲームの表示の大きさ**で、全案を1枚に並べる（大きく描いてから縮めない）
- 方向をばらけさせる：体つき、頭身、輪郭、持ち物、姿勢、大きな形の組み合わせ。同じ案の言い換えを数に入れない
- 自分で「ありがち」と思う案に印を付ける。最初に浮かんだ案は、だいたいありがち

### 2. 絞る

- 3案に絞る。理由は、設計書の「一目で伝えたいこと」と、デザインの柱で書く。好みで選ばない
- ここで一度 `game-art-director` に見せてよい（方向のずれを早く止める）

### 3. 色と細部

- 3案それぞれに、パレットの中で**色の案を3つ以上**付ける
- 白黒にしても読めるか（明暗の差で形がわかるか）を確かめる
- 細部（模様、小物、表情）は、表示の大きさで見えるものだけ足す。見えない細部は設定画の注記に回す

### 4. 並べ図（ラインナップ）

- 同じ画面に出るもの（主人公、仲間、敵、小物）を、**同じ大きさの比率**で1枚に並べる
- 見分けられるかを3通りで確かめる：シルエットだけ／色だけ（ぼかす）／表示の大きさ
- ゲームの背景の上に置いて、背景に溶けないかを見る
- 敵と味方、危ないものと安全なものが、形の言葉と色で分かれているか

### 5. 清書（設定画）

1案に決めて、外の人がこれだけで描ける設定画にする。

- 正面・横（要るなら後ろ）、足元の位置と当たりの範囲
- 色コード（面ごと：明るい面と影）、線の太さ
- 比率：頭身、ほかのキャラとの身長の比（並べ図から）
- 必ず入れる特徴と、自由にしてよいところ
- 表情・状態の差分（使う場面つき）、パーツの分け方

### 6. ゲームの画面で確かめる

ゲーム（なければスタイル見本の画面）に置いて、スクリーンショットで見る。

- 実寸（対象の端末の解像度）
- 白黒
- 半分の大きさ
- いちばん混み合った場面（敵が多い、エフェクトが重なる）

### 7. 監修

- `game-art-director` が見る。「必ず直す」が0になるまで直す
- 直しは**少なくとも1回は回る**前提で予定を組む。一発で通ったら、基準が甘くないかを疑う

### 8. 決定

- 設定画を「決定」とし、資産一覧と依頼書の添付にする
- `game-content-art` は、決定した設定画から資産を作る。決定前の案から本番の資産を作らない

## 背景で見るところ

- **遊ぶ面がいちばん読める**こと：道、置ける場所、敵の通り道。明暗を3段（遊ぶ面・飾り・遠景）に分け、飾りと遠景はキャラより彩度とコントラストを下げる
- キャラ・UIが重なる場所に、大事なものを描かない
- 前景・中景・遠景、遠くから見える目印
- 地域や時間帯ごとの色の調子の変化（並べ図と同じく、全地域を1枚に並べて比べる）

## UIで見るところ

- ボタンやアイコンも、ラフを複数出して絞る（アイコンは1つにつき6案以上）
- 押せる／押せない／選ばれている、の見た目の差を、並べ図と同じく1枚に並べて見る
- いちばん小さい画面と、いちばん長い文言で確かめる

## 小さなゲームの近道

- 脇役・小物は、段階1を短く（3〜6案）、段階3と4をまとめてよい
- **主人公、よく出る敵、最初の背景は省かない**（プレイヤーが最初に見て、いちばん長く見るもの）

## 本番の絵を外で作る

設定画が決まったら、本番の絵を外で作る。依頼書の型と流れは `reference/request_sheet.md`。

- 依頼書の添付に、設定画・並べ図・画面のスクリーンショットを付ける。設定画があれば、外の人は「何を描くか」で迷わない
- 途中の確認を段階で入れる：ラフ → 線画 → 色 → 完成。各段階で `game-art-director` が見る。後の段階ほど直しは高くつくので、ラフと線画で方向を固める
- 同じキャラを何枚も頼むときは、最初に設定画（正面・横・色）の清書を頼み、それを以降の依頼書の添付にする
- 届くまでは、決定した設定画に沿った仮の絵で開発を進める

### 画像生成の道具で作るとき

道具を使うか、どれを使うか、使う範囲はオーナーが決める。

- 依頼書を、そのまま指示の元にする（「変えてはいけない」ところは、指示に必ず入れる）
- 実在の作家・作品・キャラの名前を指示に入れない
- 道具の利用規約（商用で使えるか、出てきた絵の権利、クレジット）を、`game-qa-compliance` が出典つきで確かめる。確かめられないものは「わからない」として、オーナーに渡す
- 出てきた絵も、外部の絵描きの絵と同じく、依頼書の確認の基準と監修で見る。特に、**同じキャラが毎回同じに見えるか**（顔、比率、色、必ず入れる特徴）を見る
- 資産一覧の「作った方法」と「権利」に、道具の名前と版、確かめた規約の出典を書く

## 監修の物差し（`game-art-director`）

- 遊びで読めるか：役割、向き、状態が、表示の大きさでわかるか
- 設計書の「一目で伝えたいこと」が伝わるか
- 並べて見分けられるか（シルエット、色、大きさ）
- 柱とアートディレクションに合うか
- ありがちすぎないか。既存の作品に似すぎていないか
