# デザインの柱・コアループ・スコープ：継ぎ手の工房（仮）

書いた人：game-preprod-designer（2026-11-18）。初版。
もとにしたもの：`01_企画/企画書.md`、`01_企画/市場調査.md`、`進行表.md`、`開発チーム.md`。
前提（オーナーの決め）：ターン制／発明品の動きはマス目の決まった規則で計算／スマホ縦持ち片手（PCはマウスで同じ操作）／期限なし・品質優先／MVPでも「組む→遺す→継ぐ→組み直す」の一周は全部入れ、削るのは数から。
「提案」と書いたところはこの担当の設計の案。数は目安で、03 仕様書作成で決め直す。

## デザインの柱（3つ）

### 1. 継ぐのは強さではなく、考える材料
次の代に渡るものは、設計図・癖・墓と遺品・谷の仕掛けだけ。どれも「そのままでは使えないかもしれないもの」で、次の代が組み直して初めて役に立つ。
- 削れるもの：家の能力値・当主の能力値の恒久の上乗せ、代をまたいで貯まるお金と店、遺品の性能が代ごとに上がる仕組み、傷まない仕掛け、年代記をまたいで数値が上がる解放
- 問い方：「この機能は、次の代に『どう直すか』を考えさせるか。それとも、ただ楽にするか」。ただ楽にするなら入れない

### 2. 規則は決まっている、解き方は決まっていない
同じ組み方・同じ盤面なら、必ず同じ動きになる（運の要素で結果を変えない）。そのかわり、課題に決まった「正解の道具」や「鍵になる部品」を置かない。毎回の違いは、癖 × 時代の掟 × 拾える部品 × 先祖が遺したもの、の組み合わせから出す。
- 削れるもの：命中率・会心などの確率、なめらかな物理、地形のランダム生成、特定の部品がないと解けない課題（鍵と錠の謎解き）、課題ごとの専用の仕掛け
- 問い方：「この機能は結果を運で変えるか」「この課題は、ほかの原理でも解けるか」

### 3. 親指一本で、一手ずつ動きが読める
縦持ちの片手で、全部の操作ができる。動きはターンごとに止まり、何が何を押したか・何が燃えたかが目で追える。次の手で起きることは盤面に印で出る。
- 削れるもの：リアルタイムの操作、両手・横持ちが前提の操作（回転のつまみ、2本指）、画面の上の端にしかないボタン、数字を読まないと分からない仕組み、1画面に入らない大きさの作業台
- 問い方：「片手の親指で届くか」「この動きは、1手ずつ見れば理由が分かるか」

柱がぶつかったとき：1 → 2 → 3 の順で優先する。ただし 3（片手で読める）を破る機能は、ほかの柱に合っていても MVP に入れない。

## コアループ：課題1つ（2〜4分）

```
見る ─→ 組む ─→ 試す（予行）─→ 挑む（ターン制）─→ 結果 ─→ 次の課題へ
 │       │  ↑______│              │                 │
 │       │  （外れたら組み直す）    │                 ├ 解けた：仕掛けを据える／部品を拾う／図鑑が埋まる
 │       │                         │                 ├ 引き返す：年月を使って別の課題へ
 │       └ 帳面の設計図を開く／     │                 └ 死ぬ：メタループの「遺す」へ
 │         持っている部品で組む     └ 1手ずつ：当主が動く→道具が規則どおり動く→敵・仕掛けが動く
 └ 課題の場所・掟・墓の年表の一文（危ない手がかり）・残っている仕掛け
```

各段の決め（提案）：
- **見る**：課題の場所を1画面（上半分が盤面）で見る。掟が効いているもの（濡れた木、流れる風）は盤面に印が出る。墓があれば年表の一文が読める
- **組む**：作業台（マス目、基本5×5、上限6×6・下限3×3。癖・掟・解放で広さが変わる。2026-11-18 仕様で確定）に部品を置いてつなぐ。親指で部品を下の棚から上の作業台へドラッグする。組む途中の取り消しは何度でもできる
- **試す（予行）**：作業台と同じ場所で切り替える試し場で（幅360で横に並ばないため。2026-11-18 仕様で確定）、本番と同じ規則で道具を何度でも動かせる。年月は使わない。ただし試し場は平らな空き地で、本番の地形・敵・残った仕掛けは入らない。本番の盤面では「次の1手で起きること」だけが印で見える
- **挑む**：ターン制。当主が1手（動く、道具を置く・使う・拾う）→ 道具と物が規則どおり動く → 敵と仕掛けが規則どおり動く。手は確定ボタンで決め、確定した手は戻せない（誤タップは確定の一押しで防ぐ）
- **戦いも課題の一つ**：専用の戦闘コマンドは作らない。敵もマスの上の「規則で動く物」で、追い払う・守るは道具で解く（柱2、スコープを絞る）
- **結果**：解けたら、使った道具は谷に据えて残せる（仕掛け）か、持って行くか、ばらして部品にするかを選ぶ。違う原理で解くと解き方の図鑑が埋まる

このループで続ける理由：
- 「これで行けるはず」の見込みが当たるかを、予行ですぐ見たい
- 外れても、1手ずつ止まるので「なぜそう動いたか」が見え、次の案がすぐ浮かぶ（失敗が答えの手がかりになる）
- 決まった正解がないので、手持ちの変な部品で通ったときに「自分の解き方」になる。違う原理で解くと図鑑が埋まる
- 1課題が短く、課題ごとに自動で保存されるので、電車の1駅でやめても損がない

## メタループ1：一生（1ラン、15〜25分）

```
継ぐ ─→ 谷を見る ─→ 課題を選ぶ ─→ [コアループ] × 5〜8 ─→ 死ぬ／隠居 ─→ 遺す ─→ 次の代を継ぐ
 │        │                         │                              │
 │        │                         └ 拾う：課題の場所・墓・仕掛け   ├ 帳面に書く設計図を選ぶ（ページに限り）
 │        │                           をばらして部品が増える         ├ 持っていた道具は死んだ場所に遺品として残る
 │        └ 墓、遺品、残った仕掛け、    ← 組める物が一生の中で増える   ├ 据えた仕掛けは谷に残り、年月と掟で傷む
 │          災いの進み具合が地図に出る                                └ 年表に一文が書かれる
 └ 子の候補2〜3人から選ぶ（癖を見る）／この代の掟が1〜2個引かれる／帳面を開く
```

- **組み直す**はこのループの頭で起きる：帳面の設計図を開くと、今の当主の癖と今の掟で動いた結果が予行で見える。親のときと違う動きを見て、どこを直すかを考える
- 一生の長さ：年月を課題の数で数える（1課題＝8年、寿命60歳。一代目3課題、二代目から5課題）。死ぬか、隠居を選ぶか、寿命で終わる。老いると「老いの癖」が付き、道具の動きが変わる（2026-11-19 オーナーの決め「寿命あり・隠居も選べる」と数値設計。パラメータ表 6.1）
- 死はこの一生の終わりだが、年代記の終わりではない。遺品・墓の年表・設計図として次の代の材料になる（柱1）

このループで続ける理由：
- 部品が増えるほど組める物が増え、一生の後半ほど大きな仕掛けが組める
- 次の課題の場所に、先祖の墓や仕掛けが待っている。取り戻したい遺品がある
- 死ぬ前に「何を帳面に遺すか」を考え始める。自分の一生が子のための準備になる
- 癖の短所が活きる課題を見つけると、はずれの癖が当たりに変わる

## メタループ2：年代記（数代、数時間）と、年代記をまたぐ解放

```
一代目 ─→ 二代目 ─→ … ─→ 災いの主を鎮める（年代記の成功）
  └ 代ごとに：谷に墓・遺品・仕掛けが積もる  ／  災いが谷を一段進む
                                          └→ 災いが工房まで届く（家が絶える：年代記の終わり）
年代記の終わり ─→ 解放（新しい部品の系統・規則・癖・掟・課題の型を1段）─→ 新しい年代記
              └ 図鑑・家系図・年表は残る（見返すもの。強さにはならない）
```

- **災いの主の進み方**（提案、数は仕様で）：代が替わるたびに、災いが谷を一段侵す（課題の場所が荒れる、敵が増える、仕掛けが傷みやすくなる）。積もった遺品・仕掛けで後半が楽になりすぎるのを、こちらの進みで釣り合わせる（企画書のリスク4、`開発チーム.md` の game-spec-balance の観点）
- **家が絶える条件**（提案）：災いが一定の段まで進み、工房に届いたら。何代で届くか（＝年代記の長さ、代の上限）は未決（オーナー）
- **年代記をまたぐ解放**：新しい遊び方だけを足す（柱1）。数値の上乗せはしない。MVPは2〜3段（企画書）
- **次の年代記の谷**：同じ谷を続けるか、新しい谷で始めるかは未決（オーナー）。MVPの谷は1つなので、MVPでは「同じ地形の谷を、一族の跡を消して始め直す」形になる（提案）

このループで続ける理由：
- 代が替わる瞬間に「父さんの道具が、私の癖だとこう動く」という驚きがある（毎代ちがう組み合わせ）
- 谷が一族の跡でにぎやかになり、「この谷はうちが作った」と見える
- 災いが進むので、ため込まずに今の代で何かを据える理由がある
- 年代記を終えると新しい部品の系統・規則が増え、知っている課題が違う解き方になる。図鑑の空きが見える

## 最初の5分・最初の1時間（提案）

### 最初の5分（一代目の前半）
| 時間 | すること | 覚えること | 驚き |
|---|---|---|---|
| 0:00〜1:00 | 工房で一代目を見る。作業台（狭め、3×3〜4×4）に部品3種（板、重り、縄） | 部品は棚から作業台へ親指で置く | 置いただけで形が見た目に出る |
| 1:00〜2:30 | 最初の課題「渡る」（谷の割れ目）。予行で板が落ちる | 規則「重さ」「落ちる」。予行は何度でもただ | 外れた理由が1手ずつ見える |
| 2:30〜4:00 | 重りで板の端を押さえて渡る。結果画面で、作った橋を谷に据えられる | 据えた物は残る | 自分の作った橋が地図に出る |
| 4:00〜5:00 | 2つめの課題で部品「ばね」を拾う | 部品は拾って増える | ばねで、1つめの課題をもっと速く解けたと気づく |

説明の文は最小にする。最初の5分では、継承・癖・掟は見せない（企画書のリスク1）。

### 最初の1時間（一代目の死〜三代目あたり）
- **一代目の終わり（10〜15分ごろ）**：一代目の一生は短め（課題3〜4つ）にして、早めに初めての死を見せる。死ぬと「遺す」の画面で、帳面のページ（少ない）にどの設計図を書くかを選ぶ。墓と遺品が地図に出る。年表の一文で少し笑う
  - 覚える：死は損ではない。帳面はページに限りがある
- **二代目（15〜35分）**：子の候補2人から選ぶ。癖を初めて見る。掟が初めて引かれる。帳面の設計図を開くと、親のときと違う動きをする
  - 驚き：同じ設計図が別の動きをする。直し方を考えるのが楽しい（この企画の一言「親の発明を、子の癖で組み直す」）
  - 覚える：癖には長所と短所がある。掟はこの代だけ
- **三代目（35〜60分）**：一代目の墓に行き、壊れかけの遺品を取り戻して、直すかばらすかを選ぶ。二代目の仕掛けが掟で傷んでいる。災いが一段進んだのが地図で見える
  - 驚き：三代の道具が1つの仕掛けになる（企画書の3代の例）
  - 覚える：遺品・仕掛けは傷む。災いは代ごとに進む。規則5つ（重さ、落ちる、弾む、燃える、引っぱる）がひととおり出そろう

## スコープ

「あれば」は、MVPの後か、MVPの数がそろって余裕があれば足すもの。理想の形にあるものは基本「あれば」。

| 機能 | 必須／あれば／入れない | 理由 | 柱 |
|---|---|---|---|
| 作業台（マス目）で部品を置いてつなぐ | 必須 | コアの動詞「組む」 | 2、3 |
| 予行（試し場で何度でも、年月を使わない） | 必須 | 見込み→結果を短く回す。失敗の理由を見せる | 2、3 |
| 本番の盤面で「次の1手」の印 | 必須 | 決まった規則を目で読めるようにする | 3 |
| ターン制の挑む（確定ボタン、確定した手は戻さない） | 必須 | オーナーの決め。誤タップを確定で防ぐ | 3 |
| 1手ずつの再生と早送り | 必須 | 読めることと、待たされないことの両方 | 3 |
| 規則 5つ（重さ、落ちる、弾む、燃える、引っぱる） | 必須（数は削れる） | 組み合わせの爆発のもと。削る下限は仕様で（提案：3） | 2 |
| 部品 約20種・5系統 | 必須（数は削れる） | 拾う部品が代ごとに違うための幅 | 2 |
| 課題の型 約6、課題の場所 10〜15 | 必須（数は削れる） | どの型も複数の原理で解けるように作る | 2 |
| 敵 約8種＋災いの主1体（マスの上の規則で動く物） | 必須（数は削れる） | 追い払う・守るの課題に要る | 2 |
| 専用の戦闘システム（攻撃コマンド、HP削り合い） | 入れない | 道具で解く遊びが薄まる。課題の一型として扱う | 2 |
| 拾う（課題の場所・墓・仕掛けをばらして部品に） | 必須 | 一生の中で組める物が増える | 1、2 |

| 時代の掟 約8、代ごとに1〜2個 | 必須（数は削れる） | 毎代の違いのもと。親の解き方をずらす | 1、2 |
| 災いが代ごとに一段進む | 必須 | 積もった物が上乗せになるのを釣り合わせる。年代記の終わりを作る | 1 |
| 年代記の終わり（鎮める／家が絶える） | 必須 | 年代記をまたぐループの区切り | 1 |
| 年代記をまたぐ解放（新しい系統・規則・癖・掟を2〜3段） | 必須（段の数は削れる） | 新しい遊び方で続ける理由 | 1 |
| 年表の自動の一文 | 必須 | 墓の手がかりと、歴史の手ざわり | 1 |
| 解き方の図鑑、家系図 | 必須 | やり込み。強さにならない記録 | 1、2 |
| 課題ごとの自動保存 | 必須 | すき間時間でやめられる | 3 |
| 保存の書き出し・読み込み | 必須 | ブラウザの消去で年代記が消えるリスク（企画書リスク6） | — |
| 隠居（自分で代を替える） | 未決（設計の案：必須） | はずれの癖の代を消化試合にしない（リスク5）。死の重さはオーナーの未決 | 1 |
| 年を取って遊び方が変わる | 未決（オーナー） | 入れるなら癖と同じく長所・短所で | 1 |
| 能力値・家の力の恒久の上乗せ、代をまたぐお金と店 | 入れない | 「腕か強化か分からない」の原因（市場調査）。考える材料にならない | 1 |
| 確率の命中・会心・ランダムな動き | 入れない | 同じ組み方は同じ動き | 2 |
| なめらかな物理 | 入れない | オーナーの決め。読めない・同じにならない | 2、3 |
| 地形のランダム生成 | 入れない | 谷は残り、積もる物で変わる（市場調査の提案1） | 1、2 |
| 特定の部品がないと解けない課題 | 入れない | 正解の道具を作らない | 2 |
| リアルタイムの操作、両手・横持ち前提の操作 | 入れない | オーナーの決め（ターン制・縦持ち片手） | 3 |
| 作業台を1画面より大きくする・スクロールして組む | 入れない | 片手で全体が見えなくなる。深さは部品の数で出す | 3 |
| オンライン（ランキング、共有サーバー） | 入れない | サーバーなし（開発チーム.md） | — |
| 決まった種（シード）で同じ谷・掟を遊ぶ挑戦 | あれば | やり込み。サーバーなしで種を文字で共有 | 2 |
| 少ない部品で解く記録 | あれば | やり込み。図鑑の延長 | 2 |
| 地方を増やす（3〜4）、前の年代記の跡が遺跡で出る | あれば | 理想の形。MVPは谷1つ | 1 |
| 部品の系統8以上、規則10前後 | あれば | 理想の形。解放の段を増やす | 2 |
| 配偶者を選んで遺伝を組む、分家、家の技 | あれば | 理想の形。家の技は「数値の上乗せにならない使い方」に限る | 1 |
| 掟30以上、掟の組み合わせの特別な時代、癖40以上 | あれば | 理想の形 | 2 |
| 年表を絵巻で見返す、一族の旋律の変奏、代替わりの演出 | あれば | 見せ方。MVPは簡素な代替わりの画面で足りる | 1 |
| 多言語 | 未決（オーナー） | 言語が決まるまで保留（開発チーム.md） | — |
| 広告・課金など出し方による仕組み | 未決（オーナー） | 出し方が決まっていない。決まったら柱に照らして見直す | — |

MVPで数を削るときの順（提案、計画担当と合わせる）：課題の場所 → 敵の種類 → 掟 → 癖 → 部品 → 規則。規則は組み合わせのもとなので最後。どれも0にはしない（一周を壊さない）。

## プロトタイプで確かめる問い（3つ）

1. **組んで試すのが、スマホ縦持ち片手で2〜4分で気持ちいいか**
   作業台 4×4〜5×5、部品 8種前後、規則 3つ（重さ、落ちる、弾む）で課題1つ。初めての人が、親指だけで組み、予行で外れ、理由が分かって直し、解くまでが2〜4分に収まるか。指で部品が隠れて置き間違えないか。
   見るもの：かかった時間、置き間違いの回数、予行の回数、解いたときの反応（「よし」「なるほど」が出るか）。

2. **親の設計図を、子の癖と新しい掟で組み直すのが「作業」でなく「発見」になるか**
   同じ課題を一代目と二代目で解く。間に「死ぬ→遺す→継ぐ」を通し、二代目は癖1つ・掟1つが変わる。説明なしで一周の意味が分かるか。直すのが「ちょっと変えるだけ」の作業になるか、「この癖ならこう使える」の発見になるか。
   見るもの：一周を説明できるか（遊んだ後に聞く）、二代目で親の設計図をどれだけ変えたか、「もう一代やりたい」と言うか。

3. **決まった規則で、1つの課題に違う原理の解き方が出るか、そして何でも解ける道具が出ないか**
   規則 5つ・部品 約12種で、課題の型3つ（渡る、運ぶ、追い払う）。何人かが遊んで、1つの課題に違う原理の解き方が3つ以上出るか。逆に、どの課題も同じ1つの道具で解けてしまわないか。
   見るもの：課題ごとの解き方の種類、同じ道具を使い回した割合、作り手が想定しなかった解き方の数。
